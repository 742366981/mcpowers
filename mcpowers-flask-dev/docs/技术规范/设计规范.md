# 设计规范

本文档定义需求文档和设计文档的编写标准。

---

## 1. 需求文档规范

### 1.1 需求文档必须包含的章节（基础框架）

| 章节 | 说明 | 强制 |
|:-----|:-----|:-----|
| 项目概述 | 名称、背景、目标 | 是 |
| 系统定位 | 边界、核心功能、用户角色 | 是 |
| 功能需求 | 模块划分、功能点列表 | 是 |
| 非功能需求 | 性能、安全等（如有） | 否 |
| 数据字典 | 核心数据实体及关系 | 是 |

### 1.2 需求提取原则（强制）

**原始需求可能以多种形式出现**（文字描述、截图、手写、语音转录等），必须确保转换后的需求文档精确完整：

| 提取原则 | 说明 |
|:---------|:-----|
| **不遗漏** | 原始需求中的每个功能点、每个字段都必须体现在需求文档中 |
| **不添加** | 需求文档只描述原始需求中的内容，不自行添加未提及的功能 |
| **可追溯** | 每个需求点应能追溯到原始需求的来源 |

### 1.3 字段识别要求（强制）

| 字段类型 | 识别特征 | 处理方式 |
|:---------|:---------|:---------|
| **下拉框字段** | 枚举值明确但可能扩展、用户从列表选择 | 基础数据表 |
| **可配置参数** | 明确说了"后台配置"/"可配置"/"可维护" | 基础数据表 |
| **业务字典** | 状态、类型、分类、标签等 | 基础数据表 |
| **写死的值** | 当前写死但未来可能变化 | 基础数据表（预判） |
| **纯静态值** | 明确不会变化、不会扩展 | 写死 |

## 2. 设计文档规范

### 2.1 设计文档必须包含的章节（基础框架）

| 章节 | 说明 | 强制 |
|:-----|:-----|:-----|
| 系统概述 | 项目定位、主要功能 | 是 |
| 技术选型 | 后端/前端/数据库/缓存等 | 是 |
| 技术规范 | 遵循的规范清单 | 是 |
| 系统架构 | 模块划分、目录结构 | 是 |
| 接口设计 | 核心接口列表 | 是 |
| 数据字典 | 表结构、字段说明 | 是 |
| 基础数据模块设计 | 基础数据表结构、接口设计 | 是 |

### 2.2 项目类型识别（强制）

| 项目类型 | 识别依据 | 必须遵守的技术规范 |
|:---------|:---------|:------------------|
| 后端 + Flask | 需求涉及 HTTP API、后端逻辑 | API规范.md、Flask后端规范.md |
| 前端 + Vue | 需求涉及页面、组件、路由 | Vue前端规范.md |
| 全栈 | 同时包含后端和前端 | 按实际技术栈确定 |
| 爬虫 | 需求涉及数据采集、爬取 | 爬虫规范.md |
| 脚本/工具 | 需求为离线工具、脚本 | 按实际技术确定 |

### 2.3 基础数据模块设计（强制）

**基础数据模块必须单独设计**，包含以下内容：

#### 基础数据表结构

| 表名 | 说明 | 字段说明 |
|:-----|:-----|:---------|
| order_status | 订单状态 | id, code, name, sort_order, is_active |
| product_category | 商品分类 | id, code, name, parent_id, level, sort_order, is_active |

**表结构设计要求**：
- 必须包含 `id`（主键）、`code`（编码）、`name`（名称）
- 必须包含 `sort_order`（排序）、`is_active`（是否启用）用于管理
- 级联数据（如分类）必须包含 `parent_id`、`level`

#### 基础数据接口设计

| 接口模式 | 方法 | 路径 | 说明 |
|:---------|:-----|:-----|:-----|
| 列表 | GET | `/{项目前缀}/base_data/{表名}/` | 获取所有启用的基础数据 |
| 详情 | GET | `/{项目前缀}/base_data/{表名}/{id}/` | 获取单条基础数据 |
| 创建 | POST | `/{项目前缀}/base_data/{表名}/` | 新增基础数据 |
| 更新 | PUT | `/{项目前缀}/base_data/{表名}/{id}/` | 更新基础数据 |
| 删除 | DELETE | `/{项目前缀}/base_data/{表名}/{id}/` | 删除基础数据 |

## 3. 设计阶段执行流程

### 3.1 需求分析阶段

```
1. 读取原始需求
2. 识别项目类型（后端/前端/爬虫等）
3. 识别所有下拉框、可配置字段
4. 输出：需求文档（含字段处理方式）
```

### 3.2 技术选型阶段

```
1. 列出可选技术栈
2. 询问用户确认
3. 匹配对应的技术规范
4. 输出：确认的技术选型清单
```

### 3.3 设计输出阶段

```
1. 按本章第2节的格式编写设计文档
2. 确保包含所有强制章节
3. 确保基础数据模块独立设计
4. 询问用户确认设计文档
```

### 3.4 设计文档自检清单

- [ ] 是否识别了项目类型？
- [ ] 是否列出了遵循的技术规范？
- [ ] 是否包含完整的目录结构？
- [ ] 是否识别了所有下拉框/可配置字段？
- [ ] 基础数据模块是否独立划分？
- [ ] 每个基础数据表是否有对应的获取接口？
- [ ] 是否输出了基础数据识别清单？
- [ ] 是否询问用户确认了技术选型？
