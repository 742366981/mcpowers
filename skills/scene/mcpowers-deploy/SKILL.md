# mcpowers-deploy（部署）

> 借鉴自 superpowers（约束式清单）。
> **核心**：部署是高风险操作，**每一项检查都不能跳**。

---

## 触发即执行

### 1. 加载规范
- Read `mcpowers-shared/mcpowers-spec-index/SKILL.md`
- 加载：
  - `mcpowers-shared/docs/技术规范/部署规范.md`（**必读**）
  - `mcpowers-shared/docs/技术规范/开发环境规范.md`（**必读**）
  - `mcpowers-shared/docs/技术规范/Git规范.md`（**必读**）
  - `mcpowers-shared/docs/技术规范/测试规范.md`

### 2. 部署前检查清单（HARD-GATE）
**任何一项不通过，停止部署**。

- [ ] **代码已合并到主分支**（或部署分支）
- [ ] **主分支最新 commit 是部署目标**（不是过期的）
- [ ] **全量测试通过**（`pytest` / 框架对应测试命令）
- [ ] **全量 lint / type check 通过**
- [ ] **依赖锁定**（`requirements.txt` / `package-lock.json` 已更新）
- [ ] **数据库迁移已就绪**（migration 文件已生成）
- [ ] **配置文件已准备**（不同环境的配置已切换）
- [ ] **环境变量已配置**（不提交到 git）
- [ ] **密钥已更新**（API key / DB password / 证书）
- [ ] **回滚方案已就绪**（上一个版本可快速回滚）
- [ ] **监控 / 告警已配置**（能看到新版本状态）
- [ ] **相关人员已通知**（团队 / 值班）
- [ ] **变更窗口确认**（业务低峰期）

### 3. 部署执行
按部署规范的具体步骤执行：
- 拉取最新代码
- 安装依赖
- 数据库迁移
- 静态资源收集
- 重启服务
- 健康检查

### 4. 部署后验证
- [ ] **健康检查接口通过**（`/health` / `/ping`）
- [ ] **核心接口冒烟测试**（登录、关键业务）
- [ ] **监控指标正常**（无异常告警）
- [ ] **日志无异常**（ERROR 级别）
- [ ] **响应时间正常**（无明显下降）

### 5. 输出部署报告
```markdown
# 部署报告

## 基本信息
- 部署时间：2024-XX-XX HH:MM
- 部署环境：生产 / 预发 / 测试
- 部署版本：v1.2.3（commit xxxxxxx）
- 部署人：xxx

## 检查清单
- [x] 所有项通过

## 部署过程
- 14:30 开始部署
- 14:35 拉取代码完成
- 14:40 依赖安装完成
- 14:45 DB 迁移完成
- 14:50 服务启动
- 14:55 健康检查通过
- 15:00 冒烟测试通过

## 验证结果
- 健康检查：✅
- 核心接口：✅
- 监控：无异常
- 日志：无 ERROR

## 回滚状态
- 上一版本：v1.2.2，已就绪
```

---

## 紧急回滚

如果部署后发现严重问题：
1. **立即回滚**（不等确认）
2. 调 `mcpowers-git-rollback` 回滚
3. 排查问题
4. 修复后重新部署

---

## 反模式（禁止）

- ❌ 跳过检查清单
- ❌ 测试没全绿就部署
- ❌ 高峰期部署
- ❌ 没回滚方案就部署
- ❌ 部署后不验证
- ❌ 改代码和部署一起做（应分开 commit）

---

## 何时中断并询问用户

- 用户没指定部署环境（生产 / 预发 / 测试）
- 检查清单有项不通过
- 用户说"快速部署"跳过验证 → 拒绝并解释
- 没有回滚方案
