# 开发环境规范

本文档定义项目开发环境的标准初始化流程，确保不同项目、不同语言、不同开发者之间的环境一致性。

---

## 1. 项目初始化流程（强制）

### 1.1 初始化检查清单

每个新项目创建时，必须按顺序执行：

| 步骤 | 操作 | 说明 |
|:-----|:-----|:-----|
| 1 | **执行 `git init`** | 初始化 Git 仓库，后续才能遵守 Git 规范 |
| 2 | 创建 .gitignore | 根据项目类型自动识别并创建 |
| 3 | 创建语言特定文件 | 如 requirements.txt 等 |
| 4 | 创建虚拟环境脚本 | 如 venv_windows.bat |
| 5 | 创建配置文档 | 敏感字段直接写在 `config_{env}.ini`，**不创建 `.env.example`**（v4.1.0+ 与禁读环境变量铁律对齐） |
| 6 | 更新记忆文件 | 记录虚拟环境路径 |

> ⚠️ **`git init` 必须首先执行**
>
> 只有初始化 Git 仓库后，才能创建 `.gitignore` 并遵守后续的 Git 规范（如 commit 规范）。
>
> **跳过条件**：使用 `git rev-parse --git-dir` 判断当前目录是否有独立的 Git 仓库：
> - 执行 `git rev-parse --git-dir`，检查返回路径是否在**当前目录**下
> - 返回 `/path/to/current/dir/.git` → 独立仓库，跳过 git init
> - 返回 `/path/to/parent/.git` → 在上级仓库中，**需要执行 git init**
>
> > ⚠️ **禁止使用 `git rev-parse --is-inside-work-tree`**，因为它会向上查找上级仓库，导致误判。
> >
> > **检查示例**：
> > ```bash
> > cd /d/project && git rev-parse --git-dir  # 返回 /d/project/.git → 独立仓库
> > cd /d/project/sub && git rev-parse --git-dir  # 返回 /d/project/.git → 需要 git init
> > ```

>
> - **runtime 解析为** `~/.claude/plugins/cache/mcpowers/mcpowers/{version}/`（**带版本号**，例 `2.27.0/`）——这是 Claude Code 插件机制安装与 `/plugin` → Update now 更新的产物；当前激活版本以该目录下 `.in_use/<pid>` 标记为准

> - 实测自检：`bash -c 'echo "[$CLAUDE_PLUGIN_ROOT]"'` 在普通 shell session 返回空字符串——印证它**不**进 shell 进程环境
>

>
> **AI 在 Bash / Read / Edit 工具输入里**：用 `${CLAUDE_PLUGIN_ROOT}/skills/mcpowers-shared/...` 让框架替换 —— **不**直接 `~/.claude/...`。
>
> **不**在 .py / .sh / .js / .ts 源文件运行时读 `CLAUDE_PLUGIN_ROOT`（**不是环境变量**，运行时不存在）——这与 `代码规范.md`「本技能禁止使用环境变量」铁律同源。详见 `代码规范.md §最高铁律 · mcpowers 注入路径稳定性`。

|:-----|:---------|

| 生产环境 | `docker-compose -f docker-compose.prod.yml up -d --build` |

### 4.3 备用启动方式（可选）

> 仅在用户明确要求时使用

| 方式 | 启动命令 | 用途 |
|:-----|:---------|:-----|
| 本地调试 | `python app.py` | 开发调试 |

### 4.4 启动/重启规则

> ⚠️ **当用户说"启动"或"重启"时（包括各种说法，如启动项目、重启服务等）**

- 重启服务（默认，覆盖 99% 场景）：`docker-compose -f docker-compose.{环境}.yml up -d --force-recreate`
- 用户明确说"重新构建"（依赖变了才需要）：`docker-compose -f docker-compose.{环境}.yml up -d --build`

> `--build` 会重新构建镜像，docker compose 会自动检测到镜像变化并重建容器，无需额外加 `--force-recreate`。
> `--force-recreate` 的作用是"强制重建容器"，仅在**容器没变、镜像也没变**的场景下需要——比如代码通过 volume 挂载更新了，但容器还在用旧进程。

### 4.5 非 Flask 项目

> ⚠️ **非 Flask 项目**：如需调整 docker-compose 格式，可参考 `Flask后端规范.md` 第21章

### 4.6 禁止事项

- ❌ **禁止**使用主要启动方式以外的命令，除非用户明确要求
- ❌ **禁止**修改启动命令，除非用户明确要求

#### 3.3.2 requirements_windows.txt

#### 3.3.3 venv_windows.bat

> ⚠️ **必须保证 Windows CMD 双击直接能跑通**——不允许依赖 PowerShell 独占语法、不允许源文件编码缺损致中文乱码、不允许占位符未替换。§3.3.4「Windows .bat 编写规范」定义 6 条铁律，本节模板是其中一种落地形式。

```bat
@echo off
REM 创建 Python 虚拟环境（{项目名}）

REM 切换 UTF-8 代码页，确保中文路径/文件名不乱码
chcp 65001 > nul

echo [1/5] Upgrading system pip...
python -m pip install -U pip || goto :error

echo [2/5] Creating venv...
python -m venv "../venv/{项目名}-env" || goto :error

echo [3/5] Activating venv...
cd "../venv/{项目名}-env/Scripts" || goto :error
call activate.bat || goto :error

echo [4/5] Upgrading venv pip...
python -m pip install -U pip || goto :error

echo [5/5] Installing requirements...
python -m pip install -r "../../../{项目名}/requirements_windows.txt" || goto :error

echo.
echo Done. Activate later: cd ../venv/{项目名}-env/Scripts ^&^& activate
pause
exit /b 0

:error
echo.
echo [FAILED] Please check the error above and re-run.
pause
exit /b 1
```

#### 3.3.4 Windows .bat 编写规范（总章·全栈适用铁律）

所有 mcpowers 生成的 `.bat` 脚本（开发环境规范 / 爬虫规范 / 部署规范 / 其他）**必须**遵守以下 6 条铁律，确保 Windows CMD 双击直接能跑通：

| 铁律 | 内容 | 反例 |
|:-----|:-----|:-----|
| **R1 CMD 优先** | 脚本必须能在 Windows CMD（`cmd.exe`）双击直接跑通；**禁用** PowerShell 独占语法（`Activate.ps1` / `$env:` / `-File` / `Set-ExecutionPolicy`） | `Activate.ps1` 直接点会报「无法加载，因为在此系统上禁止运行脚本」 |
| **R2 编码处理** | 含中文 echo / 中文路径 / 中文文件名 → 首行 `chcp 65001 > nul`（切换 UTF-8 代码页）；源文件用 UTF-8 BOM 编码避免双重解码异常；纯英文脚本可省 | 中文 echo 不加 chcp 会出现「锟斤拷」乱码 |
| **R3 不写中文 echo / 中文 REM**（强烈推荐） | 进度提示统一英文（`echo [1/5] ...`），彻底回避 R2 的 chcp + BOM 双重保险；如必须中文，先确认源文件 UTF-8 BOM + `chcp 65001 > nul` 双保险 | `echo 创建虚拟环境...` 在 GBK 默认 CMD 下必乱码 |
| **R4 路径双引号** | 含空格的路径必须 `"..."` 包裹；命令与参数间空格分隔，参数**不**裹进引号；建议所有路径统一加引号防意外 | `python "../venv/xxx env/Scripts/python"`（参数被引号吞掉） |
| **R5 activate 写法** | 必须 `call activate.bat`（CMD 自动解析 PATHEXT）；**禁止**只用 `activate`（依赖 PATHEXT，PowerShell 环境易卡住）；**禁止** `Activate.ps1`（CMD 不能直接跑） | `call activate` 在 Windows Terminal 默认 PowerShell 标签会失败 |
| **R6 错误处理** | 每步关键命令接 `|| goto :error`；脚本末尾设 `:error` 段输出失败信息 + `pause` + `exit /b 1`；禁止失败后继续跑后续步骤 | `python -m venv ...` 失败仍继续 `cd` 进不存在的目录 |

**两种风格范式**：

**A. 多行 + 错误处理 + 暂停**（venv 创建 / 启动服务 / 看日志等需要保留窗口的场景）：

```bat
@echo off
chcp 65001 > nul

echo [1/3] Step one...
cmd1 || goto :error

echo [2/3] Step two...
cmd2 || goto :error

echo [3/3] Step three...
cmd3 || goto :error

echo Done.
pause
exit /b 0

:error
echo [FAILED] Please check the error above and re-run.
pause
exit /b 1
```

**B. 单行 `&&` 链式**（脚本短、任一失败即停、不需要保留窗口的场景）：

```bat
cmd1 && cmd2 && cmd3
```

**风格选择指南**：

| 场景 | 推荐风格 | 理由 |
|:-----|:---------|:-----|
| 一次性脚本（venv 创建 / 初始化数据库 / 更新依赖） | A 多行 | 失败易调试，用户能看到哪步挂了 |
| 启动服务 / 长驻进程 / 持续看日志 | A 多行 + 末尾 `pause` | 启动失败窗口停留看错；启动成功窗口停留看实时输出 |
| CI / 无人值守 | B 单行 | 无 `pause` 不卡住；无中文 echo 无编码问题 |
| 工具脚本（git pull + 重启等组合操作） | A 多行 | 用户交互场景，需要看反馈 |

爬虫规范 §25「Windows .bat 编写规范」给出 4 类典型模板：一键启动 / 一键关闭 / `{module}_windows.bat` / `update_windows.bat`。

## 4. 虚拟环境路径管理（强制）

### 4.1 路径规范（强制）

**虚拟环境统一放在项目平级的 `venv/{项目名}-env` 目录**：

```
workspace/
├── venv/
│   └── {项目名}-env/        ← 虚拟环境目录
│       ├── Scripts/          ← Windows
│       └── bin/              ← Unix
└── {项目名}/                ← 项目目录
    ├── apps/
    └── ...
```

**路径格式**：
- Windows：`../venv/{项目名}-env/Scripts/python`
- Unix：`../venv/{项目名}-env/bin/python`

### 4.2 记忆文件更新（强制）

#### 4.2.1 路径记录格式

| 路径类型 | 格式 | 用途 |
|:---------|:-----|:-----|
| 相对路径 | `../venv/{项目名}-env/Scripts/python` | AI 执行命令时切换环境 |
| 绝对路径 | `<实际路径>/python.exe` | 用户查看/配置 IDE |

#### 4.2.2 更新内容

将虚拟环境路径记录到 `docs/细节记录/` 中：

```markdown
## 环境信息

| 日期 | 内容 | 用途/关联 |
|-----|------|----------|
| 2024-01-01 | 虚拟环境：`../venv/{项目名}-env/Scripts/python` | 环境切换 |
```

### 6.1 每次工作前检查（强制）

**开始工作前必须检查以下项目**：

| 检查项 | 操作 | 如果异常 |
|:-------|:-----|:---------|
| 虚拟环境是否存在 | 检查虚拟环境可执行文件是否存在 | 提示用户创建 |
| 依赖是否完整 | 检查依赖列表是否完整 | 提示用户安装依赖 |

**⚠️ Windows 路径命令格式规范**：
> 路径必须用双引号包起来，参数放在引号外面，用空格分隔
> - ✅ `"../venv/xxx/Scripts/python" --version`
> - ❌ `"../venv/xxx/Scripts/python --version"` （参数被包进引号）

**按项目类型执行检查命令**：

| 项目类型 | 检查命令 |
|:---------|:---------|
| Python | `"../venv/{项目名}-env/Scripts/python" --version` |
| Python | `"../venv/{项目名}-env/Scripts/pip" list` |
| Node.js | `node --version` |
| Node.js | `npm list` |
| Go | `go version` |
| Java | `java -version` |
| Java | `mvn --version` 或 `gradle --version` |
