# mcpowers-requirement-change（需求变更）

> **mcpowers 自身设计**，基于 `代码同步修改规范.md` + `细节记录规范.md`。
> **核心**：一次变更找全所有引用点，避免系统不一致。

---

## 编排

本技能按顺序调用以下方法层技能 + 规范：

| 步骤 | 调用对象 | 类型 | 触发条件 | 失败时 |
|:-----|:---------|:-----|:---------|:-------|
| 1 | 规范组（`代码同步修改规范` + `细节记录规范`） | 规范 | 必读 | 提示加载 |
| 2 | 引用点穷举搜索 | 内联 | 必走 | 漏一处则中断 |
| 3 | 同步修改 | 内联 | 引用点全部找到后 | 逐点验证 |
| 4 | `mcpowers-git-commit` | 场景 | 一致性确认 | 阻断提交 |

**保护路径**：`mcpowers-shared/`、`mcpowers/`、`hooks/` 三个目录的写操作触发前确认。

**铁律**：禁止只改一处导致系统不一致；禁止不记录变更细节。

---

## 触发即执行（5 步）

### 1. 明确变更范围
- 用户说"加个字段" → 哪个表的字段？加在哪个 API？哪个前端页面？
- 用户说"改流程" → 原来流程是什么？新流程是什么？涉及哪些角色？
- 输出：**变更影响清单**（哪些文件/模块/文档需要改）

**加载规范**（先 Read 索引）：
- Read `mcpowers-shared/mcpowers-spec-index/SKILL.md`
- 按查表加载：
  - `代码同步修改规范.md`（**必读**）
  - `细节记录规范.md`（**必读**）
  - 对应栈规范（Flask / Vue / 数据库 等）
  - 涉及 API → `API规范.md`
  - 涉及设计 → `设计规范.md`

**v2.3.0 接口契约补充（条件加载）**：
- 变更**涉及接口签名 / 参数 / 路径 / 错误码 / 响应结构** → **必读** `docs/技术规范/接口契约规范.md`
- 必改项：
  - 视图函数 / Controller 的 docstring（5 字段 + description 简短 ≤ 100 字 + parameters/responses 完整结构化）
  - 接口响应 schema（如改 `data` 字段、新增错误码）
  - 接口路径（如模块改名、操作名变化）
- **禁止**：改业务代码不改 docstring（线上文档失真 → 前端调用报错 → 客服投诉）

### 2. 找全引用点（关键步骤）
按变更清单，**用工具穷尽搜索**：
- `Grep` 旧字段名 / 旧函数名 / 旧接口名
- 查数据库迁移历史（`migrations/`）
- 查 API 文档
- 查前端调用
- 查测试用例
- 查相关文档（README / 设计文档）

**输出**：
```
变更影响：
- 后端：models/user.py（改 User 加 phone）、api/auth.py（登录接口）
- 前端：src/views/Login.vue（加手机号输入）
- 数据库：migrations/versions/xxxx_add_phone.py
- 文档：docs/接口文档.md、README.md
- 测试：tests/test_auth.py
```

### 3. 同步修改
按清单**逐项修改**，每改一项记录：
- 改了什么文件
- 改了什么内容
- 是否影响其他文件

### 4. 验证一致性
- 跑测试
- 启动服务手动验证
- 检查 API 文档和实际接口是否一致
- 检查 README 是否需要更新

### 5. 记录变更
按 `细节记录规范.md` 追加：
```markdown
## 2024-XX-XX 需求变更
**原因**：业务调整，登录方式改为手机号
**影响**：5 个文件
**操作人**：AI
**备注**：原 email 字段保留，但改为非必填
```

## 收尾

- 调 `mcpowers-git-commit` 提交
- 提交信息模板：
  ```
  feat(变更类型): 简要说明
  
  - 改动了哪些文件
  - 关联的需求/issue
  ```

---

## 何时中断并询问用户

- 变更范围不清（"加个字段"不知道加在哪）
- 多个引用点之间存在冲突
- 变更影响已上线数据（需不需要数据迁移）
- 涉及多个团队/模块的边界

---

## 反模式（禁止）

- ❌ 只改一处不考虑引用（导致系统不一致）
- ❌ 改完代码不更新文档
- ❌ 改完不记录（下次不知道为啥改的）
- ❌ 改完不跑测试
- ❌ 改完不 commit / 多个变更合一个 commit

---

## 完成后自检清单

- [ ] 变更清单已穷尽（Grep 验证）
- [ ] 所有引用点已同步修改
- [ ] 测试通过
- [ ] API 文档 / README 已更新
- [ ] 变更已记录到细节文档
- [ ] 代码和文档已同 commit
