# 自动化测试规范

本文档定义栈无关的自动化测试编排规范（含 Web UI、API、全栈 E2E 及专项测试）。**新增自动化默认使用 Python；已有测试套件沿用原语言和框架；用户明确指定时以用户指定为准。**

> **核心原则**：**证据侦察 → 测试 → 报告 → 修复** 闭环；bug 必须**二维分类**（严重度 × 归属端）
>
> **适用范围**：本规范服务于 `mcpowers-autoTest` 技能，沉淀语言/运行器/驱动选型、项目证据规则、bug 分级标准、报告 JSON schema。

---

## 1. 测试范围与工具选型

### 1.1 测试范围与默认组合

> **默认策略**：新建或补写自动化测试默认使用 Python + pytest；执行已有套件时沿用项目现有语言和框架，不为统一语言而迁移。

| 范围 | Python 默认组合 | 证据或显式指定时的适配 | 适用场景 |
|:-----|:----------------|:-----------------------|:---------|
| Web UI 自动化 | `pytest + Playwright-Python` | `pytest + DrissionPage`、`pytest + Selenium-Python`；已有或指定 Cypress / Playwright-Node / WebdriverIO 时沿用 | 页面渲染、用户流、浏览器交互 |
| API 自动化 | `pytest + requests` | 异步场景：`pytest-asyncio + httpx/aiohttp`；已有 unittest、Robot、Supertest 等时沿用 | 纯接口验证、轻量、快 |
| 全栈 E2E | Python API + `Playwright-Python` | 按项目已有 API/UI 套件分层执行，不强行统一 | 前后端联调、完整业务流 |

### 1.2 工具角色与选型表

| 工具角色 | Python 默认/推荐 | 证据或显式指定时的适配 | 说明 |
|:---------|:-----------------|:-----------------------|:-----|
| 测试运行器 | pytest | unittest、Robot Framework、JUnit 等 | 负责发现、fixture、断言和报告 |
| 浏览器自动化 | Playwright-Python | DrissionPage、Selenium-Python；Node 版仅已有或指定 | 负责页面和浏览器交互 |
| HTTP 客户端 | requests | httpx、aiohttp | 负责发请求，不是测试运行器；异步 API 需配 `pytest-asyncio` |
| OpenAPI 契约 / Fuzz | Schemathesis | Dredd、Newman | 详细生成流程复用 `API测试自动生成.md` |
| 移动端 | Appium-Python-Client | Detox、Maestro、其他 Appium 语言绑定 | 需要明确设备/模拟器环境 |
| 性能测试 | Locust | k6、JMeter | 压测方案与优化走 `mcpowers-optimize` |

> **选择优先级**：用户明确指定 > 已有测试套件/配置 > 项目依赖与 CI/脚本证据 > 项目技术栈推断 > Python 默认。
>
> **未知框架处理**：没有依赖、配置或现有用例证据时，不得凭 AI 熟悉度引入框架；先输出推荐依据并询问用户。

### 1.3 项目证据与 DrissionPage 适用条件

#### 1.3.1 证据分级

| 级别 | 证据 | 行为 |
|:-----|:-----|:-----|
| 🎯 已确认 | 现有测试导入、配置文件、CI/脚本已有执行命令 | 沿用该框架 |
| ⚠️ 高概率 | 依赖或运行脚本存在，但没有对应测试文件 | 可推荐，执行前展示依据 |
| ❓ 默认 | 没有框架证据 | 使用 Python 默认，创建/安装前询问 |

检查顺序：用户要求 → 现有测试文件与 fixture → 配置文件 → 依赖声明与锁文件 → CI/脚本 → 技术栈。目录名或 AI 熟悉度不能单独决定框架。

#### 1.3.2 DrissionPage 适用条件

| 条件 | 处理 |
|:-----|:-----|
| 用户明确指定 DrissionPage | 使用 `pytest + DrissionPage` |
| 项目依赖、导入或 fixture 已使用 DrissionPage | 沿用现有组合 |
| 明确要求接管本机浏览器或测试国内站点 | 优先推荐 DrissionPage，并展示依据 |
| 普通新建 Web UI、没有上述证据 | 使用 `pytest + Playwright-Python` 默认 |

DrissionPage 是浏览器自动化驱动，不替代 pytest 的测试发现、fixture、断言和报告职责。

## 2. 命名约定（强制）

复用 `测试规范.md §7.1.1` 的 test_/tmp_ 前缀约定，**新增**：

| 场景 | 命名规则 | 示例 |
|:-----|:---------|:-----|
| 自动化测试文件 | Python 默认 `test_*.py` / `*_test.py`；已有 `at_*.py` 配置时沿用 | `tests/at_e2e/test_login.py` |
| 自动化测试用例 | `at_{module}_{seq}`（报告 test_id） | `at_login_001` |
| 报告 JSON | `reports/auto_test_{YYYYMMDD}_{HHMMSS}.json` | `reports/auto_test_20260714_153000.json` |
| 报告摘要 | `reports/auto_test_{YYYYMMDD}_{HHMMSS}.md` | 同上 |
| 自动化测试数据 | `at_test_{field}` | `at_test_email` |
| 缓存键 | `at:{module}:{key}` | `at:user:session:123` |

## 3. 二维 Bug 分类

### 3.1 严重度维度

| 级别 | 定义 | 修复 SLA | 示例 |
|:-----|:-----|:---------|:-----|
| **P0 致命** | 阻塞主链路 / 数据丢失 / 安全漏洞 | 立即 | 生产环境登录失败、订单数据丢失 |
| **P1 高** | 核心功能错 / 主要流程断 | 24h | 列表分页错、导出失败 |
| **P2 中** | 次要功能错 / 边界 bug | 1 周 | 排序错、空状态显示 |
| **P3 低** | 体验问题 / 文档错 | 下版本 | 错别字、UI 偏移 |

### 3.2 归属端维度

| 归属端 | 标识符 | 典型问题 | 默认路由 |
|:-------|:-------|:---------|:---------|
| 前端 | `frontend` | Vue/CSS/JS 错 | `mcpowers-bugfix`（前端侧） |
| 后端 | `backend` | API/Python 错 | `mcpowers-bugfix`（后端侧） |
| 数据库 | `database` | schema/SQL 错 | `mcpowers-bugfix`（数据库侧） |
| 配置 | `config` | ini/yaml/env 错 | 直接改配置（不调技能） |
| 缓存 | `cache` | Redis 键值错 | `mcpowers-bugfix`（缓存侧） |
| 第三方 | `thirdparty` | 外部 API/SDK 错 | 暂停 + 排查 |
| 基础设施 | `infra` | Docker/网络/磁盘 | 暂停 + 运维 |
| 未知 | `unknown` | 无法判断 | **强制**人审 |

### 3.3 归属端识别规则（AI 实现）

| 报错线索 | owner |
|:---------|:------|
| `apps/xxx/views.py:42` | backend |
| `frontend/src/components/Foo.vue:18` | frontend |
| `migrations/versions/xxx.py:5` | database |
| `config/prod.ini` 缺键 | config |
| `redis.exceptions.ConnectionError` | cache |
| `requests.exceptions.SSLError` | thirdparty |
| `OSError: [Errno 28] No space left` | infra |
| 其他 | unknown（标红 + 人审） |

## 4. 报告 JSON Schema（强制）

### 4.1 顶层结构

```json
{
  "report_id": "auto_test_20260714_153000",
  "generated_at": "2026-07-14T15:30:00+08:00",
  "test_scope": "fullstack",
  "tool_stack": ["pytest", "playwright-python"],
  "summary": {
    "total": 50,
    "passed": 45,
    "failed": 5,
    "by_severity": {"P0": 1, "P1": 2, "P2": 2, "P3": 0},
    "by_owner": {"frontend": 2, "backend": 3}
  },
  "failures": [
    {
      "test_id": "at_login_001",
      "test_name": "登录成功",
      "severity": "P1",
      "owner": "backend",
      "error_message": "AssertionError: expected 200 got 500",
      "stack_trace": "...",
      "file_location": "apps/auth/views.py:42",
      "reproduction_steps": [
        "POST /api/auth/login",
        "body: {username:'admin', password:'123456'}",
        "expected: code=0, token returned"
      ],
      "suggested_fix": "检查 login() 的密码校验逻辑",
      "affected_files": ["apps/auth/views.py:42", "tests/at_login.py:18"],
      "routing": "mcpowers-bugfix"
    }
  ]
}
```

> 💡 **`reproduction_steps` 写法差异**（按 test_scope）：
>
> | test_scope | 步骤格式 | 示例 |
> |:-----------|:---------|:-----|
> | **API** | `[HTTP方法 路径, body, 期望响应]` | `["POST /api/auth/login", "body: {username, password}", "expect: code=0, token"]` |
> | **Web UI** | `[打开页面, 操作元素, 期望结果]` | `["打开 /login", "填表 + 点击提交", "expect: 跳转 /dashboard"]` |
> | **全栈 E2E** | 先 API 准备数据 → UI 验证 | `["API: POST /api/seed", "UI: 打开 /list 验证", "expect: 新数据可见"]` |

### 4.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|:-----|:-----|:-----|:-----|
| `report_id` | string | ✅ | 时间戳唯一标识 |
| `generated_at` | ISO 8601 | ✅ | 生成时间 |
| `test_scope` | enum | ✅ | `webui` / `api` / `fullstack` |
| `tool_stack` | array | ✅ | 分开记录运行器、驱动和客户端，如 `["pytest", "drissionpage"]` |
| `summary` | object | ✅ | 统计摘要 |
| `failures` | array | ✅ | 失败用例数组 |
| `failures[].test_id` | string | ✅ | 命名：`at_{module}_{seq}` |
| `failures[].severity` | enum | ✅ | `P0` / `P1` / `P2` / `P3` |
| `failures[].owner` | enum | ✅ | `frontend` / `backend` / `database` / `config` / `cache` / `thirdparty` / `infra` / `unknown` |
| `failures[].error_message` | string | ✅ | 断言失败信息 |
| `failures[].stack_trace` | string | ✅ | 完整堆栈（定位 owner 的核心证据） |
| `failures[].file_location` | string | ✅ | 主报错位置 |
| `failures[].reproduction_steps` | array | ✅ | 复现步骤 |
| `failures[].suggested_fix` | string | - | AI 建议的修复方向 |
| `failures[].affected_files` | array | ✅ | 受影响文件列表 |
| `failures[].routing` | enum | ✅ | `mcpowers-bugfix` / `direct` / `pause` |

### 4.3 Markdown 摘要模板

```markdown
# 自动化测试报告 - 2026-07-14 15:30

## 摘要

| 总数 | 通过 | 失败 | 通过率 |
|:-----|:-----|:-----|:-------|
| 50 | 45 | 5 | 90% |

## 按严重度

| 级别 | 数量 | 修复 SLA |
|:-----|:-----|:---------|
| P0 | 1 | 立即 |
| P1 | 2 | 24h |
| P2 | 2 | 1 周 |

## 按归属端

| 归属端 | 数量 | 推荐路由 |
|:-------|:-----|:---------|
| backend | 3 | mcpowers-bugfix |
| frontend | 2 | mcpowers-bugfix |

## 失败详情

### [P1][backend] at_login_001 登录成功

- **错误**：`AssertionError: expected 200 got 500`
- **位置**：`apps/auth/views.py:42`
- **建议**：检查 login() 的密码校验逻辑
- **路由**：`mcpowers-bugfix`
```

## 5. 修复路由（强制）

### 5.1 路由表

| owner | 默认路由 | 调用方法 |
|:------|:---------|:---------|
| frontend | `mcpowers-bugfix` | 调 bugfix，前端侧 |
| backend | `mcpowers-bugfix` | 调 bugfix，后端侧 |
| database | `mcpowers-bugfix` | 调 bugfix，DB 侧 |
| config | `mcpowers-bugfix` | 调 bugfix，配置侧（ini/yaml/env） |
| cache | `mcpowers-bugfix` | 调 bugfix，缓存侧 |
| thirdparty | 暂停 + 排查 | 不自动调，需要人工 |
| infra | 暂停 + 运维 | 不自动调，需要人工 |
| unknown | 暂停 + 标红 | **必须**人审 |

### 5.2 路由冲突处理（多端问题）

一条失败用例横跨多端时：

1. **拆分**：AI 自动拆成多条 single-owner 报告
2. **优先级**：P0 > P1 > P2 > P3；同级别按 frontend → backend → database → config → cache → thirdparty → infra 顺序
   > 💡 **frontend 优先的 why**：前端错往往掩盖后端响应（看到红屏/空白页就以为后端坏了），先改前端可快速暴露真正的后端问题
3. **批量调用**：相同 owner 的合并调用一次 `mcpowers-bugfix`

## 6. 循环机制

### 6.1 标准循环

```
跑测试 → 生成报告 → 推荐路由 → 人审 → 修复 → 再测
   ↑                                              ↓
   └──────────── 全过 / 用户中断 ──────────────────┘
```

### 6.2 终止条件

| 条件 | 行为 |
|:-----|:-----|
| 全部通过 | 输出"全过"总结，退出 |
| 用户中断 | 保存当前报告，提示"下次继续" |
| 修复失败 | 标记 failed-fix，继续循环（最多 3 次） |
| 修复超过 3 次仍失败 | 暂停，标红，等待人审 |

> 💡 **3 次来源**：业界经验值；前 2 次通常是定位问题，第 3 次是再确认；超过则说明根因分析方向可能错了，需要人审重判。

## 7. 清理规范

复用 `测试规范.md §7.1.1` 命名约定 + `§9.2 Step 6` 清理步骤：

- 测试账号：`at_test_{module}_{seq}`
- 数据库记录：`at_` 前缀
- 上传文件：`temp/at_*.xlsx`
- 缓存键：`at:{module}:{key}`

---

## 8. ❌ 禁止（反模式）

- ❌ 不生成报告直接给修复建议
- ❌ 跳过 owner 判断直接调 `mcpowers-bugfix`
- ❌ owner=unknown 时不标红直接推荐
- ❌ 一次性修完所有 bug（必须循环验证）
- ❌ 在生产数据库跑自动化测试
- ❌ 修改生产配置（即使是测试发现问题）
- ❌ **跳过断言强制通过**（`pytest.skip()` / `test.skip()` / 删除断言）——会让问题被掩盖，下次复现更难定位
- ❌ **修改生产数据库 schema**（即使是测试发现问题）——必须用 migration 工具 + 走 code review
