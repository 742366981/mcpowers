## §1. 抓包三件套

### §1.1 Web 抓包（3 类工具按场景选择）

| 工具 | 优势 | 适用场景 |
|:-----|:-----|:---------|
| **浏览器 DevTools** | 零成本、XHR/Fetch 筛选、Initiator 调用栈 | **入门首选**，单接口断点调试 |
| **mitmproxy** | Python 脚本化、可改写请求/响应、可批量过滤 | **自动化分析首选** |
| Charles | GUI 友好、Throttle 模拟弱网、支持重发 | 人工巡检、复现问题 |
| Fiddler | Windows 友好 | Windows 环境 |

**mitmproxy 核心用法**（**必学**）：

```python
# 脚本保存为 mitm_script.py，mitmdump -s mitm_script.py
# 1. 只保留业务接口，过滤 CDN/上报
def request(flow):
    url = flow.request.pretty_url
    if any(skip in url for skip in ['.png', '.woff', 'analytics.', 'log.', 'beacon.']):
        flow.kill()  # 阻断，不传给上游
    elif any(api in url for api in ['/api/', '/graphql', 'gateway']):
        save_core_request(flow)
```

**⚠️ v2.16.0 HTTPS 解密验证清单**（**§3.9 L4 漏抓根因**）：
mitmproxy/Charles 装了证书但仍抓不到 HTTPS 接口、URL 显示空白或 `(failed)`，
按以下顺序排查：

1. **证书安装位置**：浏览器/系统证书库都要装，Chrome → 设置 → 证书管理
   → "受信任的根证书颁发机构"；macOS 需到"钥匙串访问"信任证书。
2. **代理是否被绕过**：Chrome 启用了 PAC 脚本 / VPN / `--proxy-server` 之外的
   `auto-detect` 都会绕过 mitmproxy；用 `chrome://net-internals/#proxy` 查实际代理。
3. **SSLKEYLOGFILE**：TLS 1.3 强制启用，可在 Chrome 启动命令加
   `--ssl-key-log-file=/path/to/keylog`，mitmproxy 用
   `--ssl-key-log-file` 读同一文件。
4. **解密验证命令**（必须在抓包前后各跑一次确认解密生效）：

   ```bash
   # 用 mitmproxy 代理直接 curl，验证解密
   curl -x http://localhost:8080 -I https://target.example.com/health
   # 应返回 200 + 非空 body（被 mitmproxy 解密后的明文）
   ```

> 反模式：❌ 装了证书就以为 HTTPS 一定能解密（实际解密失败时显示空 URL，
> 而不是"抓不到"——见 §3.9 L4）。

#### §1.1.1 抓包过滤器反向风险与请求类型可见性表（**v2.16.0 新增，§3.9 L5/L6**）

> **核心原则**：过滤器的目的是"去除噪音"，但**配置错时也会把目标接口过滤掉**——
> v2.15.0 缺失这一节，AI 经常凭"抓不到"误判"接口不存在"。

**L5 过滤器反向风险清单**：

| 工具 | 配置错 | 修复 |
|:-----|:-------|:-----|
| DevTools Network Filter | 误勾 Hide data URLs / Hide extension URLs / "Fetch/XHR" 单选过滤 | 取消 Hide data URLs；改为 "All" 类型 |
| mitmweb Filter | Filter pattern 写错（`api.` 应为 `api\.example\.com`） | 用空白 Filter 重试一次确认 |
| Charles / Fiddler | 启用了 "Focus" 或断点保留窗口 | 关闭 Focus；移除断点 |
| 系统代理 | Chrome 用了 PAC 脚本 / VPN 绕过 mitmproxy | 查 `chrome://net-internals/#proxy` 实际代理 |

**调试技巧**（**先做这 3 步再判定"抓不到"**）：

1. **空白 Filter 重试**：把所有过滤器清空，看是否出现目标请求
2. **Disable JavaScript 看请求类型分布**：`chrome --disable-javascript` 启动，
   或 DevTools → Settings → Disable JavaScript 看哪些请求是 JS 触发的
3. **切换 Network 标签**：从 "Fetch/XHR" 切到 "All" / "Doc" / "WS" / "EventStream"

**L6 请求类型默认可见性表**（**按类型分流监听**）：

| 请求类型 | DevTools 标签 | Playwright 监听 |
|:---------|:-------------|:----------------|
| `fetch` / `XMLHttpRequest` | Fetch/XHR | `page.on("request", lambda r: ...)` 主网络流 |
| **WebSocket** | WS | 单独 `Network.enable` + WebSocket 帧 |
| **Server-Sent Events**（`EventSource`） | EventStream | `page.on("response")` + 读 stream |
| `navigator.sendBeacon()` | **不在 Network 流** | 仅在 navigation timing |
| `fetch({ keepalive: true })` | 页面关闭瞬间丢失 | `page.on("request")` 含 keepalive 标记 |
| **HTTP/3 (QUIC)** | 大多数代理不支持 | `chrome://net-internals/#quic` 看实际连接 |
| **Prefetch / Preconnect** | DevTools 默认折叠 | DevTools → Network → 右键 → "Show Prefetch" |
| **Cache 命中** | **根本不发请求** | `chrome://net-internals/#disk-cache` |

> 反模式：❌ 只看 Fetch/XHR 标签就宣布"接口不存在"（WebSocket / SSE /
> sendBeacon / Cache 命中都不在 XHR 流——见 §3.9 L6）。

### §1.2 APP 抓包（3 层递进）

| 层级 | 场景 | 工具 |
|:-----|:-----|:-----|
| **L1 明文 HTTP** | APP 用 HTTP | mitmproxy + 用户证书（Android 7+ 需 root / iOS 需描述文件） |
| **L2 HTTPS** | APP 用 HTTPS | 同上，但需用户证书被 APP 信任 |
| **L3 SSL Pinning** | 装了证书但抓不到 | **必须绕过**（详见《爬虫Android逆向规范》§2 /《爬虫IOS逆向规范》§2） |

**⚠️ 关键提示**：抓包结果常含大量冗余（图片/字体/CDN/上报），
**必须按请求类型过滤**才能定位核心业务接口（详见主《爬虫分析规范》§3）。

## §2. 自动化基础

### §2.1 自动化浏览器（Web 抓动态接口）

> **核心思想**：人工巡检只适合看 1-2 个接口，**真正业务接口往往需要触发特定交互**
> （登录态、滑动验证、下拉刷新）才会出现。**必须用自动化工具模拟用户行为**。
>
> **v2.18.0 强化（默认工具栈切换）**：从 v2.9.3 强制 Playwright 改为
> **DrissionPage 默认**（全场景，国内/海外/分析/封装统一）；Playwright 降为
> fallback 路径（DrissionPage 弱场景 5 类——Cloudflare Bot Management / 海外 SPA 复杂交互 / 复杂 Shadow DOM / iframe 嵌套 / **重度反指纹检测** / **复杂行为分析风控**，
> 详见 §2.1 主表）。
>
> 协议层（不走浏览器的 API 直连）默认用 **`curl_cffi.requests`** 替代裸 `requests`
> （详见 §5）。

| 工具 | 优势 | 适用场景 |
|:-----|:-----|:---------|
| **DrissionPage**（v2.18.0 默认） | 国产、**接管便利性 + 国内站点适配**（5秒盾/Turnstile 自动化通过率优势）、**代码量比 Playwright 少 30~50%**、中文文档极佳、对国内站点（小红书/抖音/淘宝/1688）专项优化；**重度反指纹场景需 [rebrowser-playwright-python](https://github.com/rebrowser/rebrowser-playwright-python) / puppeteer-real-browser 配合**（DrissionPage 仍泄露 `navigator.webdriver`） | **全场景默认**（v2.18.0 起强制）：分析阶段 + 封装阶段 + 国内/海外 |
| **Playwright-Python** + `playwright-stealth` | Python 生态、跨浏览器、内置指纹伪装 | **fallback 路径**（v2.18.0 起，**v2.18.1 补**）：DrissionPage 弱场景——(1) Cloudflare Bot Management（5秒盾后还有 Turnstile/滑块/行为分析） / (2) 海外 SPA 复杂交互 / (3) 复杂 Shadow DOM / iframe 嵌套 / (4) **重度反指纹检测**（需 [rebrowser-playwright](https://github.com/rebrowser/rebrowser-playwright-python) / puppeteer-real-browser 配合）/ (5) **复杂行为分析风控**（2026 CF 行为序列/滑块轨迹/代理 IP 纯度） |
| **seleniumbase** | UC Mode（undetected-chromedriver）成熟、国外生态 | **fallback 备选**：Selenium 兼容 + UC 反检测需求 |
| Playwright-Node | Node.js 生态 | 仅当 Python 复现失败时作《爬虫Web逆向规范》§B 路径使用 |
| Puppeteer | Node.js 生态、轻量 | 简单 Chromium 场景 |
| Selenium | 多语言、老牌 | 跨语言兼容需求 |

**DrissionPage 抓全量接口示例**（**v2.18.0 默认接管模式**，
**禁止**新开窗口，详见 §3）：

```python
from DrissionPage import ChromiumPage, ChromiumOptions

# 接管用户 Chrome（先按 §3.7 启动 chrome --remote-debugging-port=9222 --remote-allow-origins=*）
co = ChromiumOptions().set_local_port(9222)
page = ChromiumPage(addr_or_opts=co)

# 接管粒度 L1：拿用户已有 tab（v2.18.0 §3.5 接管粒度 DrissionPage 映射）
if not page.tab_ids:
    raise RuntimeError("未发现用户标签页：询问后再在用户 context 新建 tab")
# 默认接管第一个 tab（按需可遍历 tab_ids 找目标域）
target_tab = page.get_tab(page.tab_ids[0])

# 拦截所有请求/响应（DrissionPage 监听 API）
target_tab.listen.start('目标接口特征 URL 或 method')
# 或全量：target_tab.listen.start()  # 拦截所有

# 模拟用户行为（链式 selector 写法，代码量比 Playwright 少 30~50%）
target_tab.get(url)
target_tab.ele('css:input[name=username]').input('xxx')
target_tab.ele('css:button[type=submit]').click()
target_tab.wait.load_start()  # 等网络空闲
```

**接管语法对照**（Playwright vs DrissionPage）：

| 任务 | Playwright（旧默认） | DrissionPage（v2.18.0 默认） |
|:-----|:---------------------|:------------------------------|
| 接管用户 Chrome | `p.chromium.connect_over_cdp("http://localhost:9222")` | `ChromiumPage(addr_or_opts=ChromiumOptions().set_local_port(9222))` |
| 拿用户已有 page | `browser.contexts[0].pages[0]` | `page.get_tab(page.tab_ids[0])` |
| 反指纹检测规避 | `playwright-stealth`（**仅做基础 webdriver 隐藏**）/ `rebrowser-playwright-python` / `puppeteer-real-browser-go`（**真反指纹**） | **无内置反指纹**（DrissionPage 仍泄露 `navigator.webdriver`；重度反指纹场景必须切 Playwright + rebrowser / puppeteer-real-browser） |
| 找元素 | `page.locator("css:input").first` | `page.ele("css:input")`（链式） |
| 点击 | `page.click("button")` | `page.ele("css:button").click()` |
| 输入 | `page.fill("input", "xxx")` | `page.ele("css:input").input("xxx")` |
| 等待 | `page.wait_for_load_state('networkidle')` | `page.wait.load_start()` |
| 网络监听 | `page.on("request", lambda req: ...)` | `page.listen.start('pattern')` |
| 截图 | `page.screenshot(path=...)` | `page.get_screenshot(path=...)` |
| 按 Esc | `page.keyboard.press("Escape")` | `page.actions.type('Escape')` 或 `page.keyboard.press('Escape')` |

> ⚠️ **v2.18.0 反例禁止**：`ChromiumPage()`（无参数）会**新开窗口**，丢失用户登录态/扩展，
> 并触发反检测。**生产代码必须用 `addr_or_opts=ChromiumOptions().set_local_port(...)`
> 接管模式**（见 §3.1 DrissionPage 接管节）。
>
> ⚠️ **v2.18.0 Chrome 150+ 强制**：DrissionPage 接管**不自动**加 `--remote-allow-origins=*`，
> 用户启动 Chrome 时必须手动加（详见 §3.7）。DrissionPage 接管**不自动**处理 Chrome 136+
> 独立 user data dir 需求，必须由用户在 `ChromiumOptions.set_user_data_path(...)` 中显式指定。

### §2.3 设备与运行时框架（**APP 逆向环境基石**）

**调试设备选择**：

| 设备类型 | 优势 | 适用场景 |
|:---------|:-----|:---------|
| **本机安卓模拟器**（MuMu / 雷电 / 夜神 / Android Studio 官方模拟器） | 免真机、root 简单、可快照回滚 | **首选**（初版逆向调试） |
| **真机调试**（USB 连接 + root + frida-server 推送） | 真实环境（部分 APP 检测模拟器）、性能稳定 | 模拟器被反调试识别 / 关键业务场景复现 |
| **云真机**（各厂商云测平台） | 覆盖多机型多系统版本 | 兼容性测试、非 root 设备场景 |

**Xposed 框架选型**（**按 Android 版本**）：

| Android 版本 | 推荐框架 | 说明 |
|:-------------|:---------|:-----|
| **Android < 7（API < 24）** | **Xposed**（原版） | 老方案，部分定制 ROM 仍可用 |
| **Android 7-10（API 24-29）** | **EdXposed** | 原 Xposed 停更后社区继任者 |
| **Android 11+（API 30+）** | **LSPosed**（**现代首选**） | 基于 Magisk，Hook 稳定性最好，需 root + Magisk 环境 |

**配套模块**：
- **justtrustme**：Xposed/LSPosed 模块，**一键绕过 SSL Pinning**（配合 LSPosed 使用）
- **TrustUserCerts**：LSPosed 模块，让 APP 信任用户证书（解决 Android 7+ APP 不信任用户证书问题）

**完整调试链路**（**真机/模拟器 + LSPosed + frida + justtrustme**）：

```
设备（root + Magisk + LSPosed + frida-server）
    ↓
安装 justtrustme / TrustUserCerts（解决证书信任）
    ↓
PC 端 mitmproxy 代理（设代理指向 PC IP:8080）
    ↓
APP 启动 → frida attach → Hook 加密函数
    ↓
mitmproxy 抓包 + frida 看入参/出参 → 还原算法
```

## §3. 浏览器与运行时复用

> **核心原则**：**默认复用用户本机 Chrome，不开新窗口**。每次新开 Playwright
> 窗口会丢失用户登录态/扩展/书签，且 `navigator.webdriver` 指纹暴露给风控。
>
> 本节的全部接管动作必须遵守主《爬虫分析规范》§1.3 铁律——**外部接管资源不可关闭**。

### §3.1 CDP attach（首选）

用户先在终端启动 Chrome（**带远程调试端口**）：

```bash
# macOS
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
  --remote-debugging-port=9222 \
  --remote-allow-origins=*

# Windows
"C:\Program Files\Google\Chrome\Application\chrome.exe" ^
  --remote-debugging-port=9222 ^
  --remote-allow-origins=*
```

Python 端 `connect_over_cdp` 接入：

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    # 接入用户本机 Chrome，复用所有 cookie/扩展/登录态
    browser = p.chromium.connect_over_cdp("http://localhost:9222")
    context = browser.contexts[0]  # 用用户已有 context，不新建
    page = context.pages[0]        # 用用户已有标签页，或 new_page() 新开标签
    # ... 抓包 / 自动化
```

### §3.2 `launch_persistent_context`（备选，仅当用户明确要"独立环境"时）

```python
context = p.chromium.launch_persistent_context(
    user_data_dir="/Users/xxx/Library/Application Support/Google/Chrome",
    headless=False,
)
```

### §3.3 禁止行为

- ❌ 每次 `p.chromium.launch(headless=False)` 新开窗口（丢失登录态 + 触发风控）
- ❌ 用 `launch(headless=True)` headless 模式抓需要登录态的接口（必然失败）
- 唯一例外：用户明确说"无 GUI 自动化"或"协议直连（不经过浏览器）"

### §3.4 接管前置预检（**v2.9.5 新增**）

> **核心原则**：AI 接到任务后的第一个动作是检测 Chrome 远程调试端口。
> **检测到接管比假设接管更可靠**。

**检测脚本**（AI 第一个动作）：

```python
import urllib.request, json

def probe_chrome_cdp(port: int = 9222, timeout: float = 2.0) -> dict:
    """探测 Chrome 远程调试，返回 {available, version, tabs}"""
    result = {"available": False, "version": None, "tabs": []}
    try:
        with urllib.request.urlopen(f"http://localhost:{port}/json/version", timeout=timeout) as r:
            ver = json.loads(r.read())
            result["available"] = True
            result["version"] = ver.get("Browser", "unknown")
    except Exception:
        return result
    try:
        with urllib.request.urlopen(f"http://localhost:{port}/json", timeout=timeout) as r:
            result["tabs"] = json.loads(r.read())
    except Exception:
        pass
    return result

# 用法
info = probe_chrome_cdp()
if info["available"]:
    print(f"✓ Chrome {info['version']} 远程调试可用，{len(info['tabs'])} 个标签页")
    for i, t in enumerate(info["tabs"]):
        print(f"  [{i}] {t['type']:8s} | {t['title'][:40]:40s} | {t['url'][:60]}")
else:
    # → 给出 AskUserQuestion 引导用户启动 Chrome 调试模式（见 §3.7）
    print("✗ 未检测到 Chrome 远程调试")
```

**预检后行为**：

| 预检结果 | AI 行为 |
|:---------|:--------|
| **可用 + 含目标域 tab** | 主动提示用户接管现有 tab（§3.6） |
| **可用 + 无目标域** | 在用户 context 内新开 tab（§3.5 L3） |
| **不可用** | AskUserQuestion 4 选 1 引导启动（§3.7） |

### §3.5 接管粒度分级（**v2.9.5 新增，v2.18.0 DrissionPage 重新映射**）

> **核心原则**：接管粒度按"用户已登录态范围"分级，**从粗到细递进**。
> **v2.18.0 起接管语法改为 DrissionPage 默认**（Playwright 作 fallback）。

| 级别 | 适用场景 | DrissionPage 代码（v2.18.0 默认） | Playwright fallback 代码 | 风险 |
|:-----|:---------|:-----------------------------------|:-------------------------|:-----|
| **L1 接管整个浏览器** | 用户已登录目标站，要复用所有登录态 | `page = ChromiumPage(addr_or_opts=ChromiumOptions().set_local_port(9222))` | `browser = p.chromium.connect_over_cdp(...)`<br>`context = browser.contexts[0]` | 无 |
| **L2 接管特定标签页** | 用户已在某 tab 打开目标页 | `target_tab = page.get_tab(page.tab_ids[i])` | `context.pages[i]` 直操作 | 低 |
| **L3 新开标签页（保留 cookie）** | 用户浏览器有 cookie 但没打开目标页 | `new_tab = page.new_tab(url)`（在用户 Chrome 上下文中新开） | `context.new_page()` 在用户 context 内新开 | 低 |

**禁止**（v2.18.0 DrissionPage 化）：
- ❌ `ChromiumPage()` 无参数调用（**v2.18.0 新增反模式**）—— 会新开窗口丢失登录态
  并触发反检测，等价于 v2.9.3 禁的 `p.chromium.launch(headless=False)`
- ❌ `p.chromium.launch(headless=False)`（v2.9.3 旧禁；v2.18.0 仍适用于 Playwright fallback）
- ❌ `browser.new_context()`（Playwright 新建独立 context，DrissionPage 无对应 API）
- ❌ `context.clear_cookies()`（清空用户登录态）
- ❌ `page.new_tab()` 不带 `url` 参数随机新开（**v2.18.0 DrissionPage 化**）—— 替代
  v2.16.0 禁的 `Target.createTarget`，attach 时会挑中自己创建的 tab 而非用户真实
  业务 tab，导致 0 个业务请求。**必须**从 `page.tab_ids` 列表中按 URL / title 匹配
  真实 page target（详见 §3.9 L3）

### §3.5.1 外部资源所有权（**v2.13.0 新增，主册 §1.3 铁律的实操落地**）

> **外部接管资源不可关闭**：通过 CDP、WebView 调试端口或外部 daemon 接管的资源
> 不属于当前任务。无论正常收尾、异常还是回退，都只能停止使用/断开客户端，
> **不能关闭用户本身的浏览器**。

接管前写入资源清单：

| resource | origin / owner | 允许操作 | 收尾 |
|:---------|:---------------|:---------|:-----|
| 用户 Chrome browser | `external/user` | attach、读取 tabs、经确认操作页面 | 断开客户端；禁止 `browser.close()` / kill |
| 用户 context | `external/user` | 复用 Cookie/登录态 | 禁止 `context.close()` / clear cookies |
| 既有 page/tab | `external/user` | 经确认读取或操作 | 禁止 `page.close()` |
| 用户 context 内任务新建 tab | `task-in-user-context` | 执行目标动作 | 默认保留；用户明确确认后才可关闭 |
| 外部 bb-browser daemon | `external` | status、adapter 调用 | 异常即回退；禁止 stop/restart |
| 任务明确启动的隔离资源 | `task` | 仅在记录的授权范围内使用 | 按创建记录清理，不影响用户资源 |

**收尾验证**：结束 Playwright 客户端后重新探测 CDP endpoint 与原 tabs，
**确认用户 Chrome、原 context 和既有 tabs 仍存活**。纯协议验收只需停止依赖
浏览器参数生成链路并独立调用模块，**禁止**为了证明"脱离浏览器"而关闭
用户 Chrome。

**反模式**：
- ❌ 接管收尾调用 `browser.close()` / `context.close()` / `page.close()` 或
  kill 用户 Chrome
- ❌ Playwright `browser.new_context()` 新建独立 context
- ❌ 任何 daemon 处理都不得关闭 / 重启 / kill 用户 Chrome

### §3.6 早检测：用户已在浏览器中打开目标页面（**v2.9.5 新增，v2.18.0 DrissionPage 化**）

> **核心原则**：如果预检时发现用户已经在某个 tab 中打开了目标域，**必须主动提示**，
> 不要重新打开丢失登录态。
> **v2.18.0 起**：接管 API 默认 DrissionPage，`page.tab_ids` 替代
> `user.contexts[i].pages`。

**检测逻辑**（v2.18.0 DrissionPage 默认）：

```python
from DrissionPage import ChromiumPage, ChromiumOptions

def find_target_tab_drissionpage(target_domain: str, port: int = 9222) -> str | None:
    """DrissionPage 接管用户 Chrome 后，在 tab_ids 中找目标域，返回 tab id 或 None"""
    page = ChromiumPage(addr_or_opts=ChromiumOptions().set_local_port(port))
    for tab_id in page.tab_ids:
        tab = page.get_tab(tab_id)
        if target_domain in tab.url and tab.tab_type == 'page':
            return tab_id
    return None

# 用法
target_id = find_target_tab_drissionpage("github.com")
if target_id is not None:
    target_tab = page.get_tab(target_id)
    print(f"✓ 检测到您已在 Chrome 中打开 github.com 的标签页（tab id={target_id[:8]}...）")
    # → 给出 AskUserQuestion 3 选 1
```

**提示话术**（AI 自动生成）：

> "检测到您已在 Chrome 中打开 `github.com` 的标签页（tab id=`xxx`，标题：`<title>`）。
> - A. 直接接管这个标签页（推荐，已登录态保留）
> - B. 在当前用户 Chrome 新开标签页（保留 cookie；默认不关闭）
> - C. 不接管，改用协议直连或由任务创建明确隔离的浏览器（需再次确认）"

> **v2.16.0 强化 + v2.18.0 DrissionPage 化**：选 A/B 时 AI 必须从 `page.tab_ids`
> 列表中按 URL / title 匹配真实 page target；**禁止**用 `page.new_tab()` 不带
> url 参数自己拉新 tab（**v2.18.0 DrissionPage 化**等价 `Target.createTarget`
> 反模式，详见 §3.9 L3）。

```python
co.set_local_port(9222)
```

### §3.8 bb-browser 与 Playwright 共享 Chrome CDP 实操（**v2.11.1 新增**）

bb-browser daemon 与 Playwright `connect_over_cdp` 共享同一用户 Chrome 是
v2.10.0 缺失的实操细节。

**启动顺序（严格，不可乱序）**：

1. 用户先启动 Chrome 调试模式（§3.5.1 前置，`chrome --remote-debugging-port=9222`）
2. 启动 bb-browser daemon（占用 9001 端口）
3. Playwright `connect_over_cdp("http://localhost:9222")`（9222 端口）
4. 复用 `browser.contexts[0]`（§3.5.1）

**端口分配（互不冲突）**：

| 端口 | 占用方 | 作用 |
|:-----|:-------|:-----|
| `9222` | 用户 Chrome | CDP endpoint（Playwright `connect_over_cdp` 目标） |
| `9001` | bb-browser daemon | MCP endpoint + adapter 调用入口 |
| 其他（9002+） | bb-browser adapter | 多 adapter 并行时占用 |

**daemon 异常处理与所有权**：

1. `curl http://localhost:9001/health` 检测 → 5xx/无响应视为异常。
2. daemon 不是当前任务明确启动的 → 标记 unavailable，直接回退 Playwright；
   **禁止 stop/restart 外部 daemon**（遵守主册 §1.3 铁律）。
3. daemon 由当前任务明确启动且资源清单 owner=`task` → 最多按创建方式重启 1 次；
   仍失败则回退。
4. 任何 daemon 处理都不得关闭 / 重启 / kill 用户 Chrome。

**共享 Chrome CDP 验证（4 步全过）**：

```bash
# 1. Chrome 9222 端口存活
curl http://localhost:9222/json/version | grep webSocketDebuggerUrl

# 2. bb-browser 9001 端口存活
curl http://localhost:9001/health

# 3. 两者能看到同一 tabs 列表
curl http://localhost:9222/json | jq '.[].url'
curl http://localhost:9001/tabs | jq '.[].url'

# 4. Playwright attach 复用用户 context
python -c "
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    b = p.chromium.connect_over_cdp('http://localhost:9222')
    print('contexts:', len(b.contexts), 'pages:', sum(len(c.pages) for c in b.contexts))
"
```

**4 步任一失败** → 未真正共享 Chrome，**禁止**进入主册 §3.0 模式 A 的
bb-browser 增强流程，强制回退纯 Playwright 链路。

## §3.9 漏抓诊断 7 层决策树（**v2.16.0 新增，v2.18.0 DrissionPage 重新映射，强门禁**）

> **核心原则**：AI 抓不到目标 URL 时，**禁止直接把"抓不到"等同于"接口不存在"**。
> 必须先按 7 层决策树自检，全部排除后才允许切协作模式。
> v2.15.0 缺失这一环，导致复杂场景漏抓关键接口后才被动切模式，浪费 1-3 轮。
> **v2.18.0 起**：接管 API 默认从 Playwright 改为 DrissionPage（`page.new_tab()` 替代
> `Target.createTarget`、`page.tab_ids` 替代 `user.contexts[i].pages`、`page.listen.start()`
> 替代 `page.on("request", ...)`）。Playwright 作 fallback。

### §3.9.1 7 层漏抓清单（按出现频率排序）

| 层 | 根因 | 现象 | 排查命令 | 修复 |
|:---|:-----|:-----|:---------|:-----|
| **L1** | CDP Target 粒度不覆盖副 Target | SPA 内部 fetch 走了 worker/iframe/service_worker 副 target，主 Network 流完全无记录 | `curl http://localhost:9222/json \| jq '.[] \| {type, url}'` | 必须按 type 分流 `Network.enable` 监听副 target |
| **L2** | Chrome 150+ 强制 Origin 校验 | `connect_over_cdp` 报 `403 Forbidden` / WebSocket handshake failed | 启动 Chrome 时漏 `--remote-allow-origins=*` | §3.7 启动命令补 `--remote-allow-origins=*`（必传） |
| **L3** | `Target.createTarget` / `page.new_tab()` 不带 url 反模式（**v2.18.0 DrissionPage 化**） | 自己拉起新 tab → attach 挑中自己创建的 tab（EAF22CC9...）而非用户真实业务 tab（4252F91C...） | `page.tab_ids`（v2.18.0 默认）/ `browser.contexts[0].pages`（Playwright fallback）列出的目标 tab 未被选中 | 禁止 `Target.createTarget` / `page.new_tab()` 不带 url；必须从 `page.tab_ids` 中按 URL / title 匹配真实 page target |
| **L4** | HTTPS 解密失败显示空 URL | mitmproxy/Charles 装了证书但 Chrome 没信任系统证书；URL 显示 `(failed)` 或空白 | `curl -x http://localhost:8080 -I https://target.example.com` 测试 | 证书安装到系统证书库；启用 SSLKEYLOGFILE（详见 §1.1） |
| **L5** | DevTools Filter 反向风险 | Hide data URLs / Fetch-XHR 单选 / mitmweb Filter pattern 错 | Disable JavaScript 看请求类型分布；用空白 Filter 重试 | 关闭 Hide data URLs / 改用所有类型 / 修正 pattern（详见 §1.1.1） |
| **L6** | 请求类型被默认隐藏 | WebSocket / SSE / sendBeacon / HTTP/3 (QUIC) / Cache 命中 / Prefetch 都不在 XHR/Fetch | DevTools 切到 "WS" / "EventStream" / "Other" 标签 | 按类型启用对应监听器（DrissionPage 用 `page.listen.start('ws://...')` 监听 WS；详见 §1.1.1） |
| **L7** | DevTools Preserving Log 未勾 / tab 错位 | SPA 路由跳转丢包；用户在 tab A 触发，AI 接管的是 tab B | DevTools → Network → Preserve log 勾选；核对 `page.tab_ids[i]` 索引（v2.18.0 DrissionPage 化） | 勾 Preserve log；用 §3.5 L2 接管正确 tab |

### §3.9.2 切换模式前的强制自检（**v2.16.0 阶段 2 强门禁，v2.18.0 DrissionPage 化**）

> AI 阶段 2 自检清单**新增 6 问**，满足"全过"才允许切协作模式 B/C/D。
> v2.18.0 起接管 API 默认 DrissionPage。

1. ☐ **L1**：已用 `curl http://localhost:9222/json | jq` 列出所有 target，确认 worker/iframe/SW target 单独 attach？

5. ☐ **L5**：DevTools Filter 是否启用了 Hide data URLs / Fetch-XHR 单选？（若是，先关闭）
6. ☐ **L6**：目标 API 是否走 WebSocket / SSE / sendBeacon / HTTP/3 / Cache 命中？（若是，切到对应 DevTools 标签；DrissionPage 用 `page.listen.start('ws://...')` 监听 WS）

## §4. 弹窗字典与处理脚本

> **核心原则**：进入页面后的第一件事是清理弹窗。**抓到弹窗内接口 ≠ 抓到核心业务
> 接口**。v2.9.4 缺失这一步，导致 Cookie 弹窗、App 下载引导、登录墙遮挡真实业务内容，
> 抓包结果严重失真。

### §4.1 8 类弹窗字典与分级策略（v2.9.5 新增）

| 类型 | 典型场景 | 分级策略 | 处理方式 |
|:-----|:---------|:---------|:---------|
| **D.1 Cookie 同意** | GDPR / 国内站首次访问 | **自动拒绝** | 优先点 "Reject All" / "拒绝可选" / "仅必需" |
| **D.2 Notification 询问** | 浏览器原生 Notification 权限 | **自动拒绝** | `context.clear_permissions()` |
| **D.3 Newsletter 订阅** | 弹窗式邮件订阅 | **自动关闭** | 点 "X / 关闭 / 不再提醒" |
| **D.4 App 下载引导** | 小红书/抖音/淘宝打开网页版 | **自动关闭** | 点 "继续访问网页版 / X" |
| **D.5 地理位置请求** | 浏览器原生 Geolocation | **自动拒绝** | `context.clear_permissions()` |
| **D.6 登录墙** | 未登录挡核心内容 | **暂停并询问用户** | 截图 + AskUserQuestion |
| **D.7 年龄验证** | 18+ / 21+ 内容站 | **暂停并询问用户** | 截图 + AskUserQuestion（合规风险） |

## §5. 协议层请求框架（**v2.9.3 新增**）

> **核心原则**：**禁止裸用 `requests` 直连 API**。裸 `requests` 的 TLS 指纹
> （JA3/JA4）一秒被风控识别为 Python 客户端。

**首选：`curl_cffi`**（**TLS 指纹伪装 + 0 配置**）

```python
from curl_cffi import requests

# 模拟 Chrome 120 浏览器 TLS 指纹 + UA
resp = requests.get(
    "https://api.example.com/v1/users",
    impersonate="chrome120",   # 关键：伪装成 Chrome TLS 指纹
    headers={"User-Agent": "Mozilla/5.0 ... Chrome/120.0 ...",  # UA 配套
             "Referer": "https://example.com/"},
    cookies={"session": "xxx"},
)
print(resp.json())
```

**关键要点**：
- `impersonate="chrome120"` → 模拟 Chrome 120 的 TLS 握手指纹
- **UA ↔ TLS 指纹必须配套**（Chrome UA 不能配 Python 默认 TLS 指纹）
- 支持 `chrome` / `chrome99` / `chrome120` / `edge` / `safari` / `firefox`
  等版本

**备选**：`httpx` + `tls-client`（需要更细控制时）

**禁止**：
- ❌ 裸 `requests.get(...)` 直连目标站 API（TLS 指纹一秒被识别）
- ❌ UA 写 Chrome 但 `impersonate` 用默认（指纹不配套，必触发风控）

## §6. bb-browser MCP 可选增强（**v2.10.0 新增 + v2.11.1 补全**）

> **核心原则**：bb-browser（[epiral/bb-browser](https://github.com/epiral/bb-browser)）
> 是**可选增强依赖**，不是硬依赖。bb-browser 通过 CDP 接管用户已运行的真实 Chrome，
> 提供 CLI / MCP server / 35+ 平台 site adapters。未安装、daemon 未运行、目标站点
> 未适配或版本不兼容时，**必须完整回退 §3 纯 CDP + Playwright + popup-handler.py 链路**。
>
> bb-browser daemon 视为外部资源，按主册 §1.3 铁律不得 stop/restart。

### §6.0 安装与 MCP 配置（**v2.11.1 新增**）

bb-browser 安装与 MCP 接入是 v2.10.0 缺失的实操环节，本节补全。

**前置要求**：
- **Node.js ≥ 18**（bb-browser 是 ESM 模块，Issue #10 报告 < 18 时 daemon 启动失败）
- 网络可访问 `registry.npmjs.org`（postinstall 拉原生二进制需要）

**安装方式（双轨 fallback）**：

| 方式 | 命令 | 适用场景 |
|:-----|:-----|:---------|
| **A. 全局安装（推荐）** | `npm install -g bb-browser` | 网络通畅，默认首选 |
| **B. 本地 + npx（fallback）** | `npm install bb-browser && npx bb-browser ...` | 全局安装 SSL 错误（Issue #6）时 |

**已知安装/启动 bug（v2.11.1 文档化）**：

| 问题 | 现象 | 触发条件 | 处理 |
|:-----|:-----|:---------|:-----|
| `Cannot find package '@bb-browser/daemon'` | daemon 启动失败（Issue #10） | tsup 打包 bug | 升级到 0.11.6+ 或 `npm rebuild bb-browser` |
| `Failed to connect to raw.githubusercontent.com:443` | postinstall 失败（Issue #6） | 网络拦截原生二进制 | 切到方案 B |

**MCP server 配置**（写入 `~/.claude/mcp_servers.json`）：
```json
{
  "mcpServers": {
    "bb-browser": {
      "command": "bb-browser",
      "args": ["daemon", "--mcp"]
    }
  }
}
```

**daemon 默认端口**：
- `localhost:9001`（bb-browser daemon + MCP endpoint）
- `localhost:9222`（用户 Chrome CDP，与 daemon 互不冲突）

**验证步骤**：
```bash

```

**任一步失败** → 视为「bb-browser unavailable」，按铁律回退 §3 纯 CDP 链路。

### §6.1 bb-browser 集成策略（**v2.10.0 新增**）

**安装**：
```bash
npm install bb-browser
```

**接管预检阶段先运行**（§3.4 的第一个动作）：
```bash

```

命令可用且 daemon 正常时，**优先使用 adapter**；需要 MCP 时按 bb-browser CLI 帮助
启动：
```bash

```

**已知 adapter 覆盖**：GitHub、Twitter/X、Reddit、V2EX，以及其他 35+ 平台；
**实际可用列表必须以当前安装版本输出为准**。**国内站点或未覆盖项目需自写 adapter**，
不得假设所有站点均受支持。

**与 §3.4 接管预检协作**：
- 先检查 `bb-browser status`，再检查 `localhost:9222`（§3.4）和目标 tab（§3.6）
- bb-browser 与 Playwright **应连接同一用户 Chrome / CDP 会话**
- 与 §3.5 接管粒度一致，**优先 L2 已打开目标 tab**，其次 L3 在用户 context 新开 tab，
  **禁止新建独立 context**

**与 §4 弹窗协同**：
- adapter 通常可处理登录前导航或公开入口，**但不替代 `popup-handler.py`**
- 仍须先清理 D.1-D.5 弹窗；D.6-D.8 **必须截图并询问用户**

**置信度联动**：
- adapter 命中后，**接口线索还要由 Playwright / `curl_cffi` 实测并保存响应**
- 验证通过后置信度自动升为 `[🎯]`（详见主册 §3.4.5）
- adapter 命中但未实测 → 只能标 `[⚠️]`，**不得直接升 `[🎯]`**

**职责边界**（与原链路不重叠）：
- **adapter**：站点级导航 / 内容入口 / 结构化操作
- **Playwright**：CDP 会话内的网络实测 / DevTools 抓包 / 浏览器自动化
- **`popup-handler.py`**：通用 DOM 弹窗 / 浏览器原生权限 / 合规询问

### §6.2 bb-browser adapter 失败判定与结果合并（**v2.11.1 新增**）

主册 §3.0 模式 A 中 bb-browser adapter 调用是"结构化线索"，但 v2.10.0 未明确
**失败如何判定、结果如何与 Playwright 实测合并**。本节补全。

**adapter 调用失败判定（4 类）**：

| 失败类型 | 判定标准 | 处理 |
|:---------|:---------|:-----|
| **超时** | 单次 `bb-browser site <site> <action>` > **30s** 未返回 | 标记 `[adapter-timeout]`，回退 Playwright |
| **命令不存在** | `bb-browser status` 显示 daemon running，但 site 命令报 `command not found` | 标记 `[adapter-not-covered]`，目标站点无 adapter |
| **返回空结构** | adapter 返回 JSON 解析后 `data == None` 或 `len(data) == 0` | 标记 `[adapter-empty]`，回退 Playwright |
| **结构不匹配** | adapter 返回字段缺 `url` / `method` / `params` 任一关键字段 | 标记 `[adapter-malformed]`，记录原始响应，回退 Playwright |

**调用日志格式（必落）**：
每次 adapter 调用必须记录到 `01-目标画像/bb-browser调用日志.log`：
```log
[2026-07-24T10:23:45+08:00] adapter=twitter/search action="AI agent" status=success duration=2.3s urls=3
[2026-07-24T10:24:12+08:00] adapter=twitter/user-detail action="@openai" status=timeout duration=30.0s urls=0
```

**结果合并规则（adapter ↔ Playwright 实测冲突时）**：

| 维度 | 优先级 | 理由 |
|:-----|:-------|:-----|
| URL 路径 / Method | **Playwright 实测优先** | 实测拿到真实响应样本 |
| 加密参数位置 | **adapter 优先** | adapter 知道站点逻辑 |
| selector / XPath | **adapter 优先** | adapter 返回站点维护者认可的稳定 selector |
| 业务语义标注 | **adapter 优先** | adapter 自带站点业务模型 |

**接口清单.md 加「来源」列（v2.11.1 新增）**：

| # | URL | Method | 置信度 | 来源 | 加密参数 | 业务含义 |
|:--|:----|:-------|:-------|:-----|:---------|:---------|
| 1 | /api/v1/user/profile | GET | [🎯] | Playwright | 无 | 用户资料 |
| 2 | /api/v1/feed | GET | [⚠️] | adapter | sign | 信息流 |
| 3 | /api/v1/tweet/post | POST | [⚠️] | adapter+Playwright | sign+token | 发推 |

**来源取值**：`adapter` / `Playwright` / `curl_cffi` / `adapter+Playwright`

**反模式**：
- ❌ adapter 调用无日志（必须落 `bb-browser-calls.log`）
- ❌ adapter URL 与 Playwright 实测 URL 冲突时直接信 adapter（实测优先）
- ❌ adapter 失败 4 类判定任一未检查就继续
- ❌ 接口清单.md 无「来源」列

## §8. 用户操作录制与重放脚本（**v2.15.0 新增**）

> **核心原则**：协作模式 B（用户操作 + AI 抓包）v2.9.5 仅为口头协议，本节
> 提供工具支撑。注意：本节**不替代** §4 弹窗清理，**不替代** §3 接管预检；
> 录制前先跑 `popup-handler.py` 的 `cleanup_all()`。

### §8.0 边界声明

对应 `user-action-recorder.py` 顶部 `DEFAULT_USER_ACTION_RECORDER` 常量：

- Playwright `record_har_path` 在 `connect_over_cdp` 模式不可用（只对 `launch()` /
  `launch_persistent_context()` 创建的 context 生效），本模块手写
  `page.on("request"/"response")` 落 JSONL；
- 录制/重放全程遵守 §3.5.1 外部资源所有权铁律（禁止 `browser.close()` /
  `context.close()` / `page.close()` / kill Chrome）；
- 本模块不替代 §4 弹窗字典、§6 bb-browser 站点级结构化操作；
- 录制前必须先跑 `popup-handler.py` 的 `cleanup_all()`，避免弹窗操作污染录制序列。
- **v2.16.0 Chrome 150+ 实战提示**：录制时 AI 必须 attach 用户真实 page target
  （如 `4252F91C4CC929918E03`），**禁止**用 `Target.createTarget` 自己拉新 tab
  后 attach；强校验表单场景 AI 不驱动表单，让用户手动点一次触发 POST，
  1s 内可抓到 200。详见主《爬虫分析规范》§3.0.6 Chrome 150+ 协作模式 B 实战案例。

### §8.1 3 个公开函数

| 函数 | 作用 | 关键参数 / 返回值 |
|:-----|:-----|:-----------------|
| `start_recording(page, output_dir)` | 启动录制（注册 page.on / 注入 DOM 事件 + 后台 flush 线程） | `page` 必须是 `connect_over_cdp` 接管的用户 page；返回 `RecorderHandle` |
| `stop_recording(handle)` | 停止 + 落 `user-actions.json` | 返回 actions_json 绝对路径 |
| `replay_actions(page, actions_json_path, screenshot_each_step=False)` | 重放 | 任一失败抛 `RecorderReplayError`；返回 `{total, success, failed, failed_steps, duration_s}` |

### §8.2 录制维度

- **5 类操作**：`click` / `fill` / `press` / `scroll` / `goto`
  - `goto` 重要（页面切换触发新接口）
  - `scroll` 触发懒加载接口
  - `press` 处理 Enter / Tab / Esc 等键盘事件
- **网络层**：每条 XHR / fetch 请求与响应（手写 `page.on("request"/"response")`
  落 `user-session.har.jsonl`）
- **弱关联 `triggers`**：每步操作时间窗 ±500ms 内触发的网络响应归并到
  `action.triggers`（v1 不做语义解析 / initiator 调用栈分析，留给 v2.16.0 B-务实）

### §8.3 selector 优先级

重放时按录制时的优先级顺序尝试匹配（v1 硬编码）：

1. `data-testid` → `[data-testid='xxx']`
2. `id` → `#xxx`
3. `name` → `[name='xxx']`
4. `aria-label` → `[aria-label='xxx']`
5. `placeholder` → `[placeholder='xxx']`
6. text 兜底 → `:has-text('xxx')`（仅 click 类型）
7. CSS path（`_cssPath()` 生成的 5 层元素路径）

匹配全部失败 → 抛 `RecorderReplayError(step_idx, reason="selector 全失效: [...]")`，
**v1 不做自愈**（YAGNI）。

### §8.4 调用方式

```python
from scripts.user_action_recorder import (
    start_recording, stop_recording, replay_actions, RecorderReplayError,
)
from scripts.popup_handler import cleanup_all

# 1) 先清弹窗（避免污染录制序列）
closed = cleanup_all(page, screenshot_dir="01-目标画像/录制/弹窗截图/")

# 2) 启动录制
handle = start_recording(page, output_dir="01-目标画像/录制/")

# 3) 用户在浏览器操作（用户主操作，AI 监控网络）

# 4) 停止并落盘
actions_path = stop_recording(handle)  # → user-actions.json
# 同时落 user-session.har.jsonl（网络请求/响应）

# 5) 后续重放（可选）
try:
    result = replay_actions(page, actions_path, screenshot_each_step=True)
    print(f"重放 {result['success']}/{result['total']} 步成功，耗时 {result['duration_s']:.2f}s")
except RecorderReplayError as e:
    print(f"重放失败 step={e.step_idx}: {e.reason}")
    # 截图已自动保存为 02-step-{i:03d}-FAILED.png
```

**工具脚本路径**：`skills/mcpowers-crawler-reverse/scripts/user-action-recorder.py`
（v2.15.0 新增工具）。

### §8.5 反模式（v2.15.0 新增）

- ❌ 跳过 §4 弹窗清理直接录制（操作序列被弹窗污染）
- ❌ 录制中关闭用户 Chrome（违反 §3.5.1 铁律）
- ❌ 把 password / token 原始 value 写入 `user-actions.json`（必须按 §8.0 脱敏黑名单过滤）
- ❌ 用 Playwright `record_har_path`（`connect_over_cdp` 不可用，必须手写 `page.on`）
- ❌ 重放失败时静默 `continue`（v1 必抛 `RecorderReplayError`）
- ❌ 把 recorder 当 popup-handler 用（职责混淆：recorder 只做录制，弹窗清理是 popup-handler 职责）
- ❌ 在 recorder 内部调用 `cleanup_all()`（违反 SOLID 单一职责，调用方按 SOP 串联）

### §8.6 JS 运行时持续监控（v2.19.0 新增）

> 协作模式 B 仅录操作 + HTTP 流量不够。`reverse-analysis-session.py web-start`
> 内部在 `start_recording()` 之后并行启动 JS 运行时监控，落 `js-runtime.jsonl`；
> `web-stop` 时 flush 剩余事件并与操作/HAR 按时间窗（默认 1000ms）关联为
> `步骤证据索引.json`，后续分析按"第 N 步 → 触发的网络 → 触发的 JS 事件"
> 直接推进，不再让 AI 从三份原始文件自由猜。

监控范围（最小但够用）：

| 通道 | 内容 | 边界 |
|:-----|:-----|:-----|
| 脚本加载 | `<script>` 标签 `src` URL | **只记元数据**，不自动保存整份源码 |
| `fetch` / XHR / WebSocket | 方法、URL、状态、有限调用栈、截断正文 | 每秒最多 20 条事件，5MB 上限 |
| `console.warn/error` | 截断 200 字符内的消息 | 不记录 `console.log` |
| `window.error` / `unhandledrejection` | 错误类型、消息、栈、文件位置 | 截断 1000 字符 |
| 关键函数 Hook | **按需由分析阶段补充**到 `03-逆向攻坚/钩子/` | v1 不做全局 Hook（避免爆量） |

注意：每条事件长度上限 1000 字符、单次 flush 上限 200 条、整体日志上限 5MB，
超出事件会被丢弃并计入 `dropped_events` 计数。

页面已打开时先补采 `performance.getEntriesByType('resource')` 中的脚本条目；
但 ready 时间点之前已加载完成的脚本**只能拿到 URL，无法补采源码**——这是浏览器
限制而非工具能力短板。AI 在分析时必须明确区分"URL 已知但源码未采到"与
"完全没有观察到"两种状态。

`web-stop` 不依赖进程退出清理：会话停止信号写入 `01-目标画像/录制/会话-XXX/.停止监控`，
长驻进程在 `finally` 中正常 flush 监听器、生成索引、保留浏览器不关闭。

### §8.7 浏览器环境与指纹一致性审计（v2.19.0 新增）

> 浏览器指纹是 Web 抓取与风控的对抗焦点。本规范**不宣称**任何工具能"100%
> 真实"，只定义**一致性审计**的最小字段、判定和门禁。

**最小字段集**（DOM + Performance API 可采）：

| 字段 | 阻断 | 警告 | 不可本地证明 |
|:-----|:-----|:-----|:-------------|
| `navigator.webdriver` | `true` | — | — |
| `navigator.userAgent` | 含 `HeadlessChrome` / 与 CDP 浏览器主版本矛盾 | — | — |
| `navigator.platform` | 与宿主 OS 明显矛盾 | — | — |
| `navigator.language` vs `Intl.locale` | — | 不一致 | — |
| 时区 | — | 与宿主配置不一致 | — |
| `screen` / `viewport` / `devicePixelRatio` | 缺失或 0 | 不合理 | — |
| `navigator.plugins` / `navigator.mimeTypes` | 缺失 | 数量 0 | — |
| WebGL `vendor` / `renderer` | — | 软件渲染（`swiftshader` / `llvmpipe`） | — |
| Canvas 两次绘制 | — | 不稳定 | — |
| 关键 API（`fetch` / XHR / WebSocket / `performance` / `crypto.subtle`） | 缺失 | — | — |
| 公网 IP / 代理出口 | — | — | **未验证**（必须保留 `unknown`） |
| TLS / JA3 / JA4 | — | — | **未验证** |
| 服务端行为画像 | — | — | **未验证** |

**门禁规则**：

- 阻断项 ≥ 1 → 停止目标业务操作，强制 `web-stop` 并写入失败状态。
- 警告项 ≥ 1 → 继续，但**必须**在 `01-目标画像/浏览器指纹报告.json` 列出。
- 工具描述中**禁止**宣称 DrissionPage "内置反指纹 / 内置指纹伪装"。
  DrissionPage 优势是**接管便利性 + 国内站点自动化通过率**（5秒盾/Turnstile
  自动化通过率），重度反指纹检测仍需 Playwright + rebrowser /
  puppeteer-real-browser 配合。

完整实现见 `skills/mcpowers-crawler-reverse/scripts/reverse-analysis-session.py`
的 `audit_browser_fingerprint()` 和 `evaluate_fingerprint()`。
