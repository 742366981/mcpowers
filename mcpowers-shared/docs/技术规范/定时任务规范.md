# 定时任务规范

本文档定义定时任务的设计规范，确保分布式、多进程环境下任务不重复执行。

---

## 1. 核心原则

> ⚠️ **无论任何情况下，任务都不能重复执行**

**两个隔离**：
1. **进程隔离**：分布式、多进程运行，同一个定时任务只能有一个进程来触发
2. **任务隔离**：同一个任务只能处理一次

---

## 2. 部署场景确认（强制）

### 2.1 首次使用定时任务

开始使用定时任务前，必须询问用户以下问题，明确部署场景：

**问题1：定时任务调度器运行在什么环境中？**

| 选择 | 说明 | 锁机制 |
|:-----|:-----|:-------|
| **单进程环境** | `python app.py` 启动，或 Docker 单容器但只用 1 个 worker | `max_instances: 1` |
| **多进程环境** | Gunicorn 多 Worker、Docker 多容器副本、Swarm 多副本等多进程 | 分布式锁 |

**问题2：如果选择多进程环境，定时任务是否与 Web 服务共用进程？**

| 选择 | 说明 | 锁机制 |
|:-----|:-----|:-------|
| **共用进程** | 定时任务调度器与 Web 服务运行在同一组进程中（如 Gunicorn 多 Worker） | 两级分布式锁 |
| **独立部署** | 定时任务调度器单独部署一个服务（独立容器/独立进程） | 只需要任务级锁 |

> ⚠️ **推荐顺序**：单进程环境 > 独立部署 > 共用进程

---

## 3. 单进程环境

### 3.1 触发条件

- `python app.py` 启动，单个 Python 进程
- Docker 容器只用 1 个 worker（如 `gunicorn -w 1`）

### 3.2 锁机制

> ⚠️ **推荐使用 Redis 任务级锁**

虽然单进程环境下 `max_instances: 1` 可以工作，但它依赖 APScheduler 内部实现，不是真正的分布式锁。

**推荐方案**：Redis 任务级锁
- 更可靠：不依赖 APScheduler 内部实现
- 便于扩展：将来升级到多进程/多机时，锁机制已经就位
- 绝对保证：任务绝对不会重复执行

### 3.3 配置

**推荐方案配置**（Redis 任务级锁）：

```python
scheduler = BackgroundScheduler(
    executors={
        'default': ThreadPoolExecutor(10)
    },
    job_defaults={
        'coalesce': False,
        'max_instances': 1  # APScheduler 层限制
    }
)
```

任务级锁实现见 5.2。

## 4. 多进程环境

### 4.1 独立部署（只需要任务级锁）

**触发条件**：定时任务调度器单独部署一个服务（独立容器/独立进程），但该服务以多进程方式运行（如 Docker 多副本、Swarm 多实例）

**锁机制**：只需要任务级锁，防止同一任务被多次处理

### 4.2 共用进程（必须使用两级锁）

**触发条件**：定时任务调度器与 Web 服务运行在同一组进程中（如 Gunicorn 多 Worker）

**问题**：多个 Worker 都会执行调度器代码，导致任务被重复触发

**解决方案**：两级分布式锁 + 看门狗机制

---

## 5. 分布式锁实现

> ⚠️ **依赖要求**：必须使用 Redis 作为分布式锁的后端存储，所有进程必须连接同一个 Redis 实例。

### 5.1 调度器级锁（进程粒度）

> ⚠️ **适用场景**：4.2 共用进程场景

**用途**：确保只有一个进程执行定时任务调度器

**键名**：`{项目前缀}:scheduler:lock:main`

**配置**：
- 过期时间：30秒
- 看门狗自动续期：每15秒续期一次
- 粒度：进程级别

**流程**：
```
gunicorn fork workers
  → 所有进程同时执行 init_scheduler
  → 休眠30秒（等待旧锁过期）
  → 竞争锁
  → 获取成功的进程启动调度器
  → 其他进程不启动调度器
```

### 5.2 任务级锁（任务粒度）

> ⚠️ **适用场景**：4.1 独立部署、4.2 共用进程场景

**用途**：确保每个具体任务只被执行一次

**键名**：`{项目前缀}:scheduler:lock:{task_type}_task:{task_id}`

**配置**：
- 过期时间：60秒
- 看门狗自动续期：每30秒续期一次
- 粒度：按任务ID

### 5.3 两级锁对比

| 锁类型 | 作用 | 粒度 | 过期时间 | 看门狗 |
|:-------|:-----|:-----|:---------|:-------|
| 调度器级锁 | 只有一个进程执行调度器 | 进程 | 30秒 | 是，15秒续期 |
| 任务级锁 | 任务不被重复执行 | 任务ID | 60秒 | 是，30秒续期 |

---

## 6. 看门狗机制（强制）

### 6.1 为什么需要看门狗

如果任务执行时间超过锁过期时间，锁会自动过期，导致其他进程可以获取同一任务的锁。

### 6.2 看门狗实现

```python
def atomic_lock_with_watchdog(self, key, ex=60):
    """获取分布式锁并自动续期（看门狗机制）"""
    acquired = self._client.set(key, '1', nx=True, ex=ex)
    if not acquired:
        return False, None

    lock_info = {'cancelled': False}

    def watchdog():
        interval = ex / 2  # 每30秒续期一次
        while not lock_info['cancelled']:
            time.sleep(interval)
            if lock_info['cancelled']:
                break
            self._client.expire(key, ex)

    watchdog_thread = threading.Thread(target=watchdog)
    watchdog_thread.daemon = True
    watchdog_thread.start()

    def release():
        lock_info['cancelled'] = True
        watchdog_thread.join(timeout=1)
        self.delete(key)

    return True, release
```

### 6.3 必须使用 finally 块释放锁

```python
try:
    # 执行任务
    ...
finally:
    if release_lock:
        release_lock()  # 停止看门狗 + 删除锁
```

## 7. 调度器级锁实现

> ⚠️ **适用场景**：4.2 共用进程场景

```python
def init_scheduler(app):
    import os
    import time

    global _app
    _app = app

    lock_key = f'{PREFIX}:scheduler:lock:main'

    # 检查锁是否存在，存在则等待旧锁过期
    if admin_redis.exists(lock_key):
        time.sleep(30)

    # 竞争锁
    acquired, release_lock = admin_redis.atomic_lock_with_watchdog(lock_key, ex=30)
    pid = os.getpid()

    if not acquired:
        print(f"[Scheduler] 进程{pid}未获取调度器锁，不启动定时任务")
        return

    print(f"[Scheduler] 进程{pid}获取调度器锁成功，启动定时任务")
    scheduler.start()
```

## 8. 任务级锁实现

> ⚠️ **适用场景**：4.1 独立部署、4.2 共用进程场景

```python
lock_key = f'{PREFIX}:scheduler:lock:{task_type}_task:{task_id}'
acquired, release_lock = admin_redis.atomic_lock_with_watchdog(lock_key, ex=60)
if not acquired:
    logger.info(f'[Scheduler] 任务锁获取失败，跳过: task_id={task_id}')
    return
```

## 9. 执行流程

```
┌─────────────────────────────────────────────────────────────┐
│                    定时器触发（间隔可配置，如每15秒）           │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  1. 查询待处理任务列表                                       │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  2. 对每个任务获取任务锁（带看门狗）                           │
│     atomic_lock_with_watchdog(task_id, ex=60)              │
│     - 成功：启动线程执行任务                                 │
│     - 失败：跳过该任务                                       │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  3. 任务执行完成后释放锁（finally块）                         │
│     release_lock()  # 停止看门狗 + 删除锁                      │
└─────────────────────────────────────────────────────────────┘
```

## 10. 配置参数

| 锁类型 | 键名 | 过期时间 | 说明 |
|:-------|:-----|:---------|:-----|
| 调度器级锁 | `{prefix}:scheduler:lock:main` | 30秒 | 进程级别，看门狗15秒续期 |
| 任务锁 | `{prefix}:scheduler:lock:{type}_task:{id}` | 60秒 | 按任务ID，看门狗30秒续期 |
| 看门狗续期间隔 | - | 过期时间的一半 | - |

---

## 11. 注意事项

| 注意事项 | 说明 |
|:---------|:-----|
| 必须使用 finally 块 | 确保无论任务成功还是异常，锁都能被释放 |
| Redis 必须同一实例 | 多进程/多机环境必须连接同一个 Redis，否则锁无法生效 |
| 日志级别 | 锁获取/释放日志使用 DEBUG 级别，不混入流程日志 |
| APScheduler 警告日志 | 配置 `logging.getLogger('apscheduler.executors').setLevel(logging.WARNING)` 抑制 missed job 警告 |

## 12. 故障排查

### 12.1 任务仍被重复执行

1. 检查是否有多个 Flask 进程：`tasklist | findstr python`
2. 检查 Redis 连接是否正常：`redis-cli ping`
3. 检查锁是否正确释放：查看日志中是否有"释放分布式锁"
4. 检查是否使用了正确的 Redis 配置（db、password）

### 12.2 锁无法获取

1. 检查 Redis 是否正常运行
2. 检查锁键是否存在残留：`redis-cli keys "{prefix}:scheduler:lock:*"`
3. 手动清理残留锁：`redis-cli del <key>`

### 12.3 任务锁过早过期

如果任务执行时间可能超过60秒，确保使用了 `atomic_lock_with_watchdog` 而非 `atomic_lock`。
