## 小程序专项流程

### 1. 宿主与目标画像

记录平台（微信/支付宝/抖音/百度等）、AppID/名称、宿主与基础库版本、普通小程序或小游戏、主包/分包、登录态、目标业务动作和授权范围。平台未知时先识别，不能套用微信术语替代其他宿主。

### 2. 包与运行时证据

- 记录包来源、哈希、主包/分包关系、页面/组件/worker/WASM 和动态加载线索。
- 定位平台请求 API、项目封装层、拦截器、登录 code/session、动态参数和宿主注入值。
- 小游戏重点补充 game loop、worker、资源加载和 WASM/Native 能力边界。
- 对无法合法获取或解包的资产保持阻塞说明，不绕过授权边界。

### 3. 接口与算法验证

通过开发者工具、代理、授权运行环境或代码证据触发真实业务动作；接口清单标来源与置信度。至少 3 组输入对照参数生成和响应；明确 code/token、宿主 session、设备/版本和分包加载的生命周期线索。

### 4. 接管资源所有权

**外部接管资源不可关闭**：开发者工具、调试浏览器、context/page、用户标签页和外部 daemon 均视为 external；收尾只停止使用/断开客户端，不关闭用户本身的浏览器或已有调试环境。任务新建页面默认保留，清理前必须明确确认。

### 5. 标准交接

按统一入口「专项证据交接合同」返回宿主/基础库/包指纹、接口证据、JS/WASM/平台 API 逆向方式、算法对照、登录与宿主状态线索、平台限制、模块输入和证据路径。

## 反模式（禁止）

- ❌ 把小程序直接当普通网页，忽略宿主 API、分包和登录 code/session。
- ❌ 微信方案无证据套到支付宝/抖音/百度。
- ❌ 普通小程序与小游戏共用同一结论，不识别 worker/WASM/资源链。
- ❌ 关闭用户浏览器、开发者工具、既有 page/tab 或外部 daemon。
- ❌ 在本技能复制公共阶段 5.5 或宣布交付 PASS。
