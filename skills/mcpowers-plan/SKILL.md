# mcpowers-plan（任务拆解）

> 借鉴自 superpowers `writing-plans`。
> **核心**：2-5 分钟可验证的小任务。任务太大 → 不好追踪；任务太小 → 上下文切换成本高。

---

## 触发即执行

### 1. 加载规范
- Read `mcpowers-shared/mcpowers-spec-index/SKILL.md`
- 加载：
  - `mcpowers-shared/docs/技术规范/代码规范.md`（基线）
  - 对应栈规范

### 2. 拆解任务
按以下原则拆解：

| 原则 | 说明 |
|:-----|:-----|
| **2-5 分钟** | 单个任务 2-5 分钟可完成并验证 |
| **可独立运行** | 完成后能跑测试 / 启动服务验证 |
| **可独立 commit** | 完成后可独立 git commit |
| **明确输入输出** | 每个任务有明确的"做什么"和"产出什么" |
| **依赖清晰** | 任务间的先后依赖关系明确 |

### 3. 输出计划文档
保存到 `docs/计划/{项目名}_{模块名}_计划.md`：

```markdown
# {模块名} 实施计划

## 总览
- 任务总数：N 个
- 预计总耗时：X 小时
- 依赖：前置需要什么

## 任务列表

### Task 1: {任务名}
- **目标**：做什么
- **步骤**：
  1. 改文件 A 第 X 行加字段
  2. 改文件 B 第 Y 函数
- **验证**：跑 `pytest tests/test_xxx.py` 应通过
- **commit**：完成后 commit 信息模板

### Task 2: {任务名}
...

## 依赖图
Task 1 → Task 2 → Task 3
Task 1 → Task 4（并行）

## 风险点
- 任务 X 可能比预期复杂
```

### 4. 交给 mcpowers-execute
计划确认后调 `mcpowers-execute` 执行。

---

## 反模式（禁止）

- ❌ 一个任务跨多个模块
- ❌ 任务无法独立验证（"重构整个项目"）
- ❌ 任务间依赖不清
- ❌ 计划过于详细（每个函数怎么写都列）→ 这是设计文档不是计划

---

## 何时跳过

- 任务 ≤ 3 步（无需拆解）
- 改动 < 100 行代码
