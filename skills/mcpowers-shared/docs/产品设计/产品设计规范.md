# 产品设计规范

本文档定义产品设计流程和原始需求规范，适用于从想法到原始需求的转换。

---

## 1. 阶段定位

```
想法/创意 → [产品设计] → 原始需求 → 需求文档 → 设计文档 → 代码
                ↑
           本阶段
```

| 阶段 | 输入 | 输出 | 依据 |
|:-----|:-----|:-----|:-----|
| 产品设计 | 想法/创意 | 原始需求文档 | 本规范 |
| 需求转换 | 原始需求文档 | 标准需求文档 | `docs/技术规范/设计规范.md` |

---

## 2. 触发条件

当用户只有想法/创意，没有具体原始需求时，执行本阶段。

**判断标准**：
- 用户表达了产品想法（如"我想做一个博客系统"）
- 但没有提供具体的用户故事、功能列表、验收标准

---

## 3. AI引导流程

### 3.1 了解基本信息

```
## 产品基本信息

请提供以下信息（如暂不确定可填写"待定"）：

| 信息项 | 说明 | 您的回答 |
|:-------|:-----|:---------|
| 产品名称 | 产品叫什么 | |
| 目标用户 | 面向哪些人群 | |
| 核心价值 | 解决什么问题 | |
| 使用场景 | 在什么情况下使用 | |
```

### 3.2 了解功能需求

```
## 功能需求

请描述核心功能（可多项）：

### 功能1：[功能名称]
- **用户故事**：作为[角色]，我希望[功能]，以便[收益]
- **验收标准**：
  - [ ] 标准1
  - [ ] 标准2
- **优先级**：P0/P1/P2
- **备注**：[如有]

### 功能2：（同上）
```

### 3.3 了解非功能需求

```
## 非功能需求

| 类型 | 说明 | 您的回答 |
|:-----|:-----|:---------|
| 性能要求 | 响应时间、并发等 | |
| 安全要求 | 认证、权限、数据安全等 | |
| 兼容性要求 | 浏览器、设备等 | |
| 其他要求 | 特殊需求 | |
```

## 4. 原始需求文档格式

生成的原始需求文档必须包含以下章节：

```markdown
# 原始需求文档

## 产品概述

### 基本信息
- 产品名称：
- 目标用户：
- 核心价值：
- 使用场景：

### 背景说明
（为什么需要这个产品）

## 功能需求

### 功能模块A

#### 功能点A.1
- **用户故事**：作为...我希望...以便...
- **验收标准**：
  - [ ]
  - [ ]
- **优先级**：P0/P1/P2

### 功能模块B
（类似结构）

## 非功能需求

| 类型 | 需求描述 |
|:-----|:---------|
| 性能 | |
| 安全 | |
| 兼容性 | |

## 约束与备注

- 已知约束：
- 风险评估：
- 备注：
```

---

## 5. 输出要求

| 要求 | 说明 |
|:-----|:-----|
| 保存位置 | `docs/原始需求/` |
| 文件命名 | `{项目名}_原始需求_{日期}.md` |
| 完整性 | 必须包含第4章所有章节 |
| 格式 | 必须符合第4章模板格式 |

---

## 6. 注意事项

| 要求 | 说明 |
|:-----|:-----|
| 交互式引导 | 不要期望用户一次性描述完整，应分步引导 |
| 追问细节 | 核心功能必须有明确验收标准 |
| 优先级 | 功能必须有优先级排序 |
| 保存确认 | 生成后必须确认用户是否满意，再保存 |
