# Flask Swagger 集成方案对比（v2.2.0 新增）

> ⚠️ **重要前提**：`Flask后端规范.md` §11 已锁定 **Flasgger** 为默认方案。
> 本文档仅供**新建项目**或**主动变更**时参考；现有 Flask 项目**无需选择**，直接用 Flasgger。

---

## 1. 三种方案总览

| 维度 | **Flasgger**（默认） | apispec + marshmallow | flask-openapi3 |
|:-----|:---------------------|:----------------------|:----------------|
| **与 Flask §11 对齐** | ✅ 完全对齐 | ⚠️ 偏离 | ⚠️ 偏离 |
| OpenAPI 版本 | Swagger 2.0 | OpenAPI 3.0 | OpenAPI 3.0 |
| 规范写法 | docstring 内联 YAML | Python 类（schema） | 装饰器 + docstring |
| 前端 TS 生成 | ✅ openapi-typescript-codegen | ✅ 同 | ✅ 同 |
| 侵入性 | 🟢 低（仅 docstring） | 🟡 中（需新增 schema 类） | 🟡 中（装饰器） |
| 生态成熟度 | 🟢 成熟 | 🟢 主流 | 🟡 新兴 |
| 学习曲线 | 🟢 低 | 🟡 中 | 🟡 中 |
| 校验能力 | ❌ 无 | ✅ marshmallow 自动校验 | ✅ pydantic 自动校验 |
| 适合场景 | **现有 Flask 项目 / 内部工具** | 新项目 / 前后端分离 | 新项目 / 想要自动 UI |

---

## 2. Flasgger（默认，与 Flask §11 完全对齐）

**优点**：
- 与 Flask 后端规范 §11 完全对齐，无需变更规范
- 改 docstring 即可，无需新增 schema 类
- 自动注册 `/apispec_1.json` + `/apidocs/` UI
- 团队已有 Flasgger 经验

**缺点**：
- Swagger 2.0（不是最新 3.0）
- 无自动参数校验（需手动 `request.json`）

**最小集成代码**（已包含在 Flask §11.1）：
```python
from flasgger import Swagger, NO_SANITIZER
Swagger(app, config={
    "specs": [{"endpoint": "apispec_1", "route": "/apispec_1.json", "rule_filter": lambda rule: True}],
    "swagger_ui": True, "specs_route": "/apidocs/",
}, sanitizer=NO_SANITIZER, template={...})
```

## 3. apispec + marshmallow

**优点**：
- OpenAPI 3.0（最新）
- marshmallow 自动校验请求体
- 更适合复杂数据模型

**缺点**：
- 需为每个接口定义 schema 类（增加代码量）
- 与 Flask §11 docstring 写法**不一致**
- 需手动写 `spec.path()` 注册路径

**最小集成代码**：
```python
from apispec import APISpec
from apispec.ext.marshmallow import MarshmallowPlugin
from marshmallow import Schema, fields

class LoginSchema(Schema):
    username = fields.Str(required=True)
    password = fields.Str(required=True)

spec = APISpec(
    title="API文档", version="1.0.0", openapi_version="3.0.0",
    plugins=[MarshmallowPlugin()],
)

@app.route('/login', methods=['POST'])
def login():
    """用户登录..."""
    spec.path(path='/login', operations={
        'post': {'requestBody': {'content': {'application/json': {'schema': LoginSchema}}},
                 'responses': {'200': {'description': '成功'}}}
    })
```

## 4. flask-openapi3

**优点**：
- OpenAPI 3.0 + 自动 Swagger UI
- 装饰器风格，集成最简单
- 支持 pydantic 校验

**缺点**：
- 与 Flask §11 docstring 写法**不一致**
- 生态相对小众，文档少
- 部分边缘 case 处理不完善

**最小集成代码**：
```python
from flask_openapi3 import OpenAPI

app = OpenAPI(__name__, info={'title': 'API文档', 'version': '1.0.0'})

@app.post('/login', summary='用户登录')
def login():
    """..."""
    return {...}
```

## 5. 选型决策树

```
你是新项目吗？
├── 是 → 想要自动校验？
│        ├── 是 → flask-openapi3（pydantic 校验）
│        └── 否 → apispec + marshmallow（OpenAPI 3.0）
└── 否（现有 Flask 项目）→ 直接用 Flasgger（Flask §11 已锁定）
```

---

## 6. 切换成本警告

| 切换路径 | 工作量 | 风险 |
|:---------|:-------|:-----|
| Flasgger → apispec | 🔴 高（每个接口改 2 处） | 中（spec 路由、加密中间件全部要重写） |
| apispec → Flasgger | 🟡 中（每个接口合并 schema + docstring） | 低 |
| Flasgger → flask-openapi3 | 🔴 高（装饰器风格全部重写） | 中 |

> 💡 **强烈建议**：选定后**不切换**。Flask §11 锁定 Flasgger 是经过团队验证的默认选择。
