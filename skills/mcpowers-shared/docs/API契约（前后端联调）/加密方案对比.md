# Flask Swagger 加密方案对比（v2.2.0 新增）

> ⚠️ **重要前提**：`Flask后端规范.md` §11.1 已实现 **HTTP Basic Auth + 仅开发/测试环境** 的默认加密策略。
> 本文档仅供**主动变更**或**特殊场景**时参考；现有 Flask 项目**无需选择**，直接沿用 Flask §11.1。

---

## 1. 四种方案总览

| 维度 | **HTTP Basic Auth + 仅开发环境**（默认） | JWT | IP 白名单 | 限流 + Token |
|:-----|:------------------------------------------|:-----|:----------|:-------------|
| **与 Flask §11 对齐** | ✅ 完全对齐 | ⚠️ 偏离 | ⚠️ 偏离 | ⚠️ 偏离 |
| 实现难度 | 🟢 低（已实现） | 🟡 中 | 🟢 低 | 🟡 中 |
| 用户体验 | 🟡 需输账号密码 | 🟢 无感知（复用业务 token） | 🟢 无感知 | 🟢 无感知 |
| 安全性 | 🟡 中（账号密码可能泄漏） | 🟢 高 | 🟢 高 | 🟢 高 |
| 适用场景 | **内部工具 / 开发环境** | 与业务统一鉴权 | 纯内网 / VPN | 生产环境 / 高安全 |
| 配置改动 | ✅ 0（沿用 §11.1） | 需新增 token 生成端点 | 需配置 IP 列表 | 需配置限流策略 |

## 2. HTTP Basic Auth + 仅开发环境（默认，与 Flask §11.1 完全对齐）

**优点**：
- Flask §11.1 已完整实现，开箱即用
- 账号密码从配置文件读取（`swagger_user` / `swagger_password`）
- 生产环境自动禁用 Swagger，完全零泄漏风险

**缺点**：
- 每次访问 `/apidocs/` 要输入账号密码
- 账号密码明文存储在配置中（需配合 `安全规范.md` 加密）

**完整实现**（Flask §11.1 已包含）：
```python
if protect:
    swagger_user = app_conf.get('swagger_user')
    swagger_pass = app_conf.get('swagger_password')

    @app.before_request
    def protect_swagger():
        swagger_paths = ['/apidocs', '/apispec_1.json', '/static/flasgger/']
        if any(request.path.startswith(p) for p in swagger_paths):
            auth = request.authorization
            if not auth or not (auth.username == swagger_user and auth.password == swagger_pass):
                return Response('Login Required', 401, {'WWW-Authenticate': 'Basic realm="Login Required"'})
```

## 3. JWT（与业务鉴权统一）

**适用场景**：前端已用 JWT 鉴权，希望 Swagger 复用同一套 token，避免重复输入账号密码。

**实现要点**：
1. Swagger 中配置 `securityDefinitions` 为 JWT
2. 前端访问 Swagger 时从 localStorage 自动读取 token
3. 仍需限制为开发环境（生产不暴露）

**最小集成代码**：
```python
# Swagger UI 中携带 token
swagger_ui_bundle_js = "//unpkg.com/swagger-ui-dist@3.52.5/swagger-ui-bundle.js"
swagger_ui_standalone_preset_js = "//unpkg.com/swagger-ui-dist@3.52.5/swagger-ui-standalone-preset.js"

template = {
    "swagger": "2.0",
    "securityDefinitions": {
        "Bearer": {"type": "apiKey", "name": "Authorization", "in": "header"}
    },
    "security": [{"Bearer": []}]
}
```

## 4. IP 白名单（纯内网 / VPN）

**适用场景**：Swagger 仅在内网或 VPN 内访问，无外部访问风险。

**实现要点**：
1. 维护 IP 白名单列表
2. `before_request` 校验来源 IP
3. 无需账号密码，体验最好

**最小集成代码**：
```python
ALLOWED_IPS = ['127.0.0.1', '192.168.0.0/16', '10.0.0.0/8']

@app.before_request
def protect_swagger_by_ip():
    if request.path.startswith(('/apidocs', '/apispec_1.json')):
        client_ip = request.remote_addr
        if not any(ipaddress.ip_address(client_ip) in ipaddress.ip_network(net) for net in ALLOWED_IPS):
            abort(403)
```

## 5. 限流 + Token（生产环境 / 高安全）

**适用场景**：生产环境需要暴露 Swagger 给外部合作伙伴，但严格控制访问频率。

**实现要点**：
1. 用 Flask-Limiter 做 IP 级别限流
2. 生成一次性 token（带过期时间）
3. 定期轮换 token + 自动失效

**最小集成代码**：
```python
from flask_limiter import Limiter
limiter = Limiter(app, key_func=lambda: request.remote_addr)

# 生成一次性 token（管理员手动生成）
@app.route('/admin/swagger-token', methods=['POST'])
def generate_token():
    token = secrets.token_urlsafe(32)
    redis.setex(f'swagger_token:{token}', 3600, 'valid')
    return {'token': token, 'expires_in': 3600}

# 校验 token
@app.before_request
def protect_swagger_by_token():
    if request.path.startswith(('/apidocs', '/apispec_1.json')):
        token = request.args.get('token') or request.headers.get('X-Swagger-Token')
        if not token or not redis.get(f'swagger_token:{token}'):
            abort(401)
```

## 6. 选型决策树

```
Swagger 会被谁访问？
├── 仅内部开发
│    ├── 有 VPN/内网 → IP 白名单
│    └── 无 VPN → HTTP Basic Auth（Flask §11.1 默认）
├── 业务前端
│    └── 已用 JWT → JWT 复用业务 token
└── 外部合作伙伴
     └── 限流 + 一次性 Token
```

---

## 7. 注意事项

| 项 | 说明 |
|:---|:-----|
| **生产环境** | 即使加密，也强烈建议**默认禁用 Swagger**（Flask §11.1 已实现） |
| **敏感接口** | 即便 Swagger 加密，业务接口仍要按 `安全规范.md` 加鉴权 |
| **账号密码** | 配置文件中禁止硬编码，配合 `安全规范.md` 使用加密配置 |
| **HTTPS** | Swagger 加密必须配合 HTTPS，否则账号密码明文传输 |

---

## 8. 反模式（禁止）

- ❌ 生产环境暴露 Swagger 且无加密（接口信息 = 业务泄漏）
- ❌ 用 HTTP Basic Auth 但配置文件中硬编码账号密码
- ❌ 加密账号密码存 git 仓库
- ❌ 加密账号密码与业务账号密码相同（隔离原则）
