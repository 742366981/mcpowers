# 开发环境规范

本文档定义项目开发环境的标准初始化流程，确保不同项目、不同语言、不同开发者之间的环境一致性。

---

## 1. 项目初始化流程（强制）

### 1.1 初始化检查清单

每个新项目创建时，必须按顺序执行：

| 步骤 | 操作 | 说明 |
|:-----|:-----|:-----|
| 1 | **执行 `git init`** | 初始化 Git 仓库，后续才能遵守 Git 规范 |
| 2 | 创建 .gitignore | 根据项目类型自动识别并创建 |
| 3 | 创建语言特定文件 | 如 requirements.txt 等 |
| 4 | 创建虚拟环境脚本 | 如 venv_windows.bat |
| 5 | 创建环境配置示例 | 如 .env.example |
| 6 | 更新记忆文件 | 记录虚拟环境路径 |

> ⚠️ **`git init` 必须首先执行**
>
> 只有初始化 Git 仓库后，才能创建 `.gitignore` 并遵守后续的 Git 规范（如 commit 规范）。
>
> **跳过条件**：如果项目已经是 Git 仓库（存在 `.git` 目录），则跳过此步骤。

## 会话首次行为

当会话开始后收到第一条消息时，AI 必须先执行 Step 1 的完整流程，再响应用户需求。

> **会话开始后的首条消息必须触发 Step 1，完成项目情况汇报后才能回答**
>
> **后续消息正常响应，不再重复执行 Step 1**

## 0. 速查表（每次任务前必须对照）

### 强制执行项
- [ ] **修改前**：必须先分析影响、询问确认
- [ ] **修改时**：必须遵守 `代码同步修改规范.md`
- [ ] **完成时**：必须立即 commit（禁止多个操作后才 commit）
- [ ] **接口开发**：必须先写 docstring，再写实现
- [ ] **代码注释**：函数/类/复杂逻辑必须有完整注释
- [ ] **临时文件**：必须放在 `temp/` 目录，用完即删
- [ ] **细节记录**：用户告知关键信息时，必须立即记录到 `docs/细节记录/`

### 禁止项
- ❌ 未经用户确认直接修改任何代码/文档
- ❌ 先写代码后补文档
- ❌ 只 commit 代码不 commit 文档
- ❌ 多个文档重复定义相同内容
- ❌ 在项目目录创建临时文件

## 1. 强制行为约束（红线）

| 红线行为 | 违规后果 |
|:---------|:---------|
| 未经确认直接修改代码/文档 | 用户有权要求回滚 |
| 先写代码后补文档 | 视为不合格 |
| 多个操作后才 commit | 视为不规范 |
| 只 commit 代码不 commit 文档 | 视为不规范 |
| 发现重复定义未处理 | 视为不合格 |
| 代码注释不完整 | 视为不合格 |
| 临时文件不清理 | 视为不规范 |
| 违反 SOLID/KISS/DRY/YAGNI | 视为不合格 |

- 无记录 → 正常开发

### 3.3 requirements_windows.txt

### 3.4 venv_windows.bat

```bat
@echo off
REM 创建 Python 虚拟环境

echo 创建虚拟环境...
python -m pip install -U pip
python -m venv ../venv/{项目名}-env

echo 激活虚拟环境...
cd ../venv/{项目名}-env/Scripts
call activate

echo 升级 pip...
python -m pip install -U pip

echo 安装依赖...
python -m pip install -r ../../../{项目名}/requirements_windows.txt

echo.
echo 完成！激活命令：cd ../venv/{项目名}-env/Scripts && activate
pause
```

## 4. 虚拟环境路径管理（强制）

### 4.1 路径规范（强制）

**虚拟环境统一放在项目平级的 `venv/{项目名}-env` 目录**：

```
workspace/
├── venv/
│   └── {项目名}-env/        ← 虚拟环境目录
│       ├── Scripts/          ← Windows
│       └── bin/              ← Unix
└── {项目名}/                ← 项目目录
    ├── apps/
    └── ...
```

**路径格式**：
- Windows：`../venv/{项目名}-env/Scripts/python`
- Unix：`../venv/{项目名}-env/bin/python`

### 4.2 记忆文件更新（强制）

#### 4.2.1 路径记录格式

| 路径类型 | 格式 | 用途 |
|:---------|:-----|:-----|
| 相对路径 | `../venv/{项目名}-env/Scripts/python` | AI 执行命令时切换环境 |
| 绝对路径 | `<实际路径>/python.exe` | 用户查看/配置 IDE |

#### 4.2.2 更新内容

将虚拟环境路径记录到 `docs/细节记录/` 中：

```markdown
## 环境信息

| 日期 | 内容 | 用途/关联 |
|-----|------|----------|
| 2024-01-01 | 虚拟环境：`../venv/{项目名}-env/Scripts/python` | 环境切换 |
```

## 6. 执行检查清单（强制）

### 6.1 每次工作前检查（强制）

**开始工作前必须检查以下项目**：

| 检查项 | 操作 | 如果异常 |
|:-------|:-----|:---------|
| 虚拟环境是否存在 | 检查虚拟环境可执行文件是否存在 | 提示用户创建 |
| 依赖是否完整 | 检查依赖列表是否完整 | 提示用户安装依赖 |

**⚠️ Windows 路径命令格式规范**：
> 路径必须用双引号包起来，参数放在引号外面，用空格分隔
> - ✅ `"../venv/xxx/Scripts/python" --version`
> - ❌ `"../venv/xxx/Scripts/python --version"` （参数被包进引号）

**按项目类型执行检查命令**：

| 项目类型 | 检查命令 |
|:---------|:---------|
| Python | `"../venv/{项目名}-env/Scripts/python" --version` |
| Python | `"../venv/{项目名}-env/Scripts/pip" list` |
| Node.js | `node --version` |
| Node.js | `npm list` |
| Go | `go version` |
| Java | `java -version` |
| Java | `mvn --version` 或 `gradle --version` |
